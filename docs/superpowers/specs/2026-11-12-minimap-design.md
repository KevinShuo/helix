# Helix 代码缩略图（Minimap）设计方案

- 日期：2026-11-12（Asia/Shanghai）。
- 调研基线：`91c1c49709009677427b48040b84d654ef113727`，当前分支 `codex/code-folding`。
- 用户目标：增加截图右侧那样的代码全局预览，交互参考 VS Code，并能在 `config.toml` 中开启、关闭。
- 用户已选择：高密度代码缩略图，并提供色块兼容模式。
- 状态：**待确认的设计文档；本次尚未实现功能，下文新增配置暂不能用于现有二进制。**

## 1. 结果与范围

在每个编辑分屏的右侧显示**当前文件**的缩略图，方便看代码分布、确认当前位置、快速导航。
全局开关影响所有编辑分屏；“全局预览”指当前文件全貌，不是把整个项目拼成一张图。

第一版包括：

1. 保留缩进、空行、代码轮廓和近似语法色的高密度缩略图。
2. 当前视口背景高亮和主光标位置标记。
3. 左键点击导航、拖动视口导航、鼠标滚轮滚动。
4. 独立的 Git 变更与诊断标记窄轨道。
5. `config.toml` 持久开关、运行时临时开关和配置重载。
6. 窄分屏自动隐藏；与函数/类折叠、软换行、函数提示、AI 行内补全共存。
7. 大文件降级、缓存失效和任务取消，避免每次重绘都扫描全文。

以下是本次提出的工程选择，并非用户逐项指定：默认关闭、仅放右侧、采用全文件适配高度的缩放方式、
默认宽度 16 个终端列。后续可增加左右侧选择、随内容滚动的 proportional 模式、搜索匹配标记、
区域标题和悬停预览。第一版不新增默认快捷键，不增加外部依赖或语言服务器请求。

VS Code 的参照行为是右侧代码概览、可点击/拖动的视口区域、可关闭的设置，见
[官方 Minimap 文档](https://code.visualstudio.com/docs/editing/getting-started/userinterface#_minimap)。
其高度缩放支持 proportional、fill、fit，见
[官方缩放说明](https://code.visualstudio.com/updates/v1_43#_minimap-sizing)。本方案先采用 fit 的思路。

## 2. 已核查的基础与约束

| 当前基础 | 入口 | 设计影响 |
| --- | --- | --- |
| 终端网格渲染 | `helix-tui/src/buffer.rs`、`helix-term/src/ui/editor.rs` | 每个终端单元只能画字符及前景/背景色，不能独立缩小字体 |
| Braille 点阵符号 | `helix-tui/src/symbols.rs` 的 `braille` | 已有 2×4 点阵映射，可直接复用 |
| 编辑区尺寸与坐标 | `helix-view/src/view.rs` 的 `inner_area`、`inner_width` | 必须统一扣除右侧空间，不能只在绘制末尾盖一层图 |
| 语法高亮 | `helix-core/src/syntax.rs` 的 `Syntax::highlighter` | 复用当前 Tree-sitter 高亮；当前 `Syntax` 不提供可直接克隆的快照 |
| 鼠标输入 | `helix-term/src/ui/editor.rs` 的 `handle_mouse_event` | 缩略图必须优先命中，避免进入正文选区和侧栏断点逻辑 |
| 实际可见源码范围 | `helix-view/src/view.rs` 的 `visible_text_ranges` | 视口定位必须考虑软换行、虚拟行及折叠 |
| 文档版本与生命周期 | `helix-view/src/document.rs`、`helix-view/src/events.rs` | 未保存文本、编辑、撤销、重载、切换语言均需更新摘要 |
| Git/诊断数据 | `Document::diff_handle`、`Document::diagnostics`、`helix-view/src/gutter.rs` | 复用已经产生的数据，不为缩略图另起 Git 命令或 LSP 请求 |
| 配置与动态命令 | `helix-view/src/editor.rs`、`helix-term/src/config.rs`、`helix-term/src/commands/typed.rs` | 已支持嵌套字段、序列化、`:set-option`、`:toggle-option`、`:config-reload` |

终端效果是“彩色点阵代码轮廓”，不会逐像素复制 GUI 中缩小的文字。
一个 Braille 字符内部的八个点共享一种前景色，因此语法色需要按覆盖面积选取代表色。
没有语法树时仍显示代码形状，使用正文默认色。

当前工作区已有其他功能的未提交修改。实现时应保留这些修改，以实际代码为准，
不能用历史折叠设计文档中“尚未实现”的描述替代当前仓库状态。

## 3. 路线比较与选择

| 路线 | 收益 | 代价/限制 | 结论 |
| --- | --- | --- | --- |
| Braille 2×4 点阵 + 色块兼容模式 | 不依赖终端图片协议；较好保留缩进和代码形状；复用现有 Surface | 语法色为近似值，字体需要正确显示 Braille | **用户已选，作为正式路线** |
| 仅用色块绘制 | 逻辑较简单，常见字体显示更稳定 | 纵向分辨率更低，代码细节更少 | 保留为上述路线中的兼容模式 |

终端图片协议需要额外的终端能力、重绘和远程兼容处理，不适合作为当前 Windows 终端版的基础方案。
它不是第一版实现依赖。

## 4. 配置接口

只开启功能时，用户增加：

```toml
[editor.minimap]
enabled = true
```

完整配置示例：

```toml
[editor.minimap]
enabled = true
width = 16
render = "braille"
min-editor-width = 60
diagnostics = true
git-diff = true
```

| 字段 | 默认值 | 含义/校验 |
| --- | --- | --- |
| `enabled` | `false` | 总开关；缺省或关闭时不占宽度，不启动摘要计算 |
| `width` | `16` | 整条缩略图区域的终端列数，包含分隔列和两条标记轨道；允许 8–40 |
| `render` | `"braille"` | `"braille"` 为 2×4 点阵，`"blocks"` 为 2×2 象限色块；其他值报配置错误 |
| `min-editor-width` | `60` | 展示缩略图后必须保留的正文最小列数，不含左侧 gutter；至少为 20 |
| `diagnostics` | `true` | 显示错误、警告等诊断轨道 |
| `git-diff` | `true` | 显示已有 diff 的新增、修改、删除轨道 |

两条标记轨道始终保留各一列，关闭某条轨道仅清空该列，避免临时开关引起正文换行变化。
字段遵循现有 `kebab-case`、默认值和 `deny_unknown_fields` 规则；类型或取值错误应指出具体字段。

持久配置沿用现有用户配置和已受信任的项目 `.helix/config.toml` 合并规则。
Windows 用户文件仍为 `%AppData%\helix\config.toml`，可用 `:config-open` 打开。
修改后执行 `:config-reload`，不需要重启。

计划复用的运行时操作：

```text
:set-option minimap.enabled true
:set-option minimap.enabled false
:toggle-option minimap.enabled
:set-option minimap.render blocks
```

这些命令仅修改当前会话，不自动写回配置文件。需要永久关闭时把文件中的 `enabled` 改为 `false`。
不另建一套独立开关命令；可在用户自己的按键映射中调用上述命令。

## 5. 布局与缩放

### 5.1 所有调用方共用同一布局结果

新增纯布局函数，输入分屏 `Rect`、gutter 宽度及 Minimap 配置，输出：
正文 `text_rect`、分隔 `separator_rect`、缩略内容 `content_rect`、Git/诊断轨道 `marker_rects`。

- 设原可用宽度为分屏宽度减 gutter，满足 `可用宽度 >= width + min-editor-width` 才显示。
- 高度取编辑区高度减状态栏一行；小于 4 行时隐藏。
- `width` 含 1 列分隔、`width - 3` 列代码内容、1 列 Git、1 列诊断。
- 状态栏保持覆盖原分屏宽度；缩略图不覆盖状态栏、分屏边框或底部 Git 窗口。
- `View::inner_area` 和 `View::inner_width` 返回相同的正文宽度。
  文本排版、软换行、光标定位、鼠标命中、行尾诊断及弹窗锚点都使用此结果。
- 开关、宽度修改、自动隐藏/重新显示后，重新校正正文水平滚动和光标可见性。

### 5.2 以真实源码行为全文件坐标

缩略图使用 `Document::text()`，不把 inlay hints、函数引用/Git 作者提示、AI 灰字等虚拟注解算作源码。
正文软换行不会增加缩略图中的源码行数。普通补全通过事务暂时更改 buffer 时，摘要按实际文档版本失效；
不能因为它是 ghost transaction 就复用已经不匹配的版本。

设 `N = max(1, text.len_lines())`，缩略内容高度为 `H`：

- Braille 的每格子像素高 `s=4`，blocks 的 `s=2`，总子像素行数 `R=s×H`。
- 使用 `P=min(N,R)` 行子像素，映射 `pixel(line)=floor(line×P/N)`。
- 小文件不拉长，一行源码占一行子像素；剩余空间留空。
- 大文件压缩到全高。一个子像素对应的源码行桶为
  `[ceil(pixel×N/P), ceil((pixel+1)×N/P))`，绘制和反向导航使用同一个函数。
- 各桶合并代码占用，不能只看每桶第一行；巨大文件降级时允许使用明确有界的抽样。
- 鼠标只有终端格精度，点击一格时取该格覆盖的源码桶中心；下方空白映射到文件末行。
  首行、末行及空文件必须有独立测试，计算使用饱和/检查算术避免越界。

横向统一观察源码前 160 个显示列，将其压缩到 `2×content_rect.width` 子像素。
保留空白缩进，超出 160 列部分截断；不随正文横向滚动改变全局轮廓。
Tab 使用当前语言缩进宽度展开；中文、emoji、组合字符按现有 grapheme/显示宽度规则处理。
每行扫描还需有字符/字节上限，避免大量零宽字符和超长单行绕过列数限制。

### 5.3 折叠与视口

源码总坐标保持稳定，折叠时仍保留被隐藏函数/类的代码轮廓。
视口背景范围由 `visible_text_ranges`、当前视口锚点及末尾可见源码推导，不能简单使用“首行 + 屏幕高度”。
第一版高亮覆盖首个到最后一个可见源码位置的包络区间，因此可能包含它们之间的已折叠函数体；
它表示当前浏览的源码跨度。主光标标记补充精确位置。空视口或只有折叠占位符时使用锚点兜底。

小视口也至少高亮一行终端格；超出文件末尾时裁剪。高亮只改变背景，不抹掉代码前景色。
同一文档的两个分屏共享源码摘要，但分别计算视口、几何和主光标位置。

## 6. 鼠标交互与编辑语义

缩略图命中必须发生在正文和 gutter 命中之前，且与绘制使用同一 `MinimapLayout`。

| 操作 | 明确行为 |
| --- | --- |
| 左键点视口外 | 聚焦所属分屏；把对应源码行滚到正文中部；目标位于折叠体内时展开包含目标的折叠 |
| 左键点视口内并拖动 | 保存抓取时鼠标相对视口顶部的偏移，以此拖动视口；避免一按下就跳动 |
| 点视口外后继续拖动 | 本次点击完成定位后开始拖动，使用新的抓取偏移 |
| 滚轮位于缩略图 | 对所属分屏执行现有滚动行为和 `scroll-lines`；结束后恢复之前的编辑焦点 |
| 拖出缩略图区域 | 继续操作最初捕获的分屏，Y 坐标夹紧到首/末行，不开始正文选区拖动 |
| 右键/中键 | 第一版消费该区域事件，不创建断点、不粘贴、不触发正文右键行为 |

沿用 Helix 现有滚动时的光标规则：光标仍在新视口内时保留，离开时只按现有逻辑调整主选区；
普通模式主选区可收缩，选择模式保留其 anchor，其他选区继续保留。
大跨度导航应提取可复用的“绝对定位视口 + 校正主光标”逻辑，不能逐屏循环滚动全文，
也不能在最后直接调用旧光标的 `ensure_cursor_in_view` 把画面拉回原处。

点击/拖动只改变视口、选区及必要的折叠状态，不改变文本或创建撤销项。
若光标/折叠改变使已有 AI 预览失效，按现有规则清理它。

拖动状态最少包括 `(ViewId, DocumentId, 布局代次, 抓取偏移)`。
左键释放必须先结束缩略图捕获并消费事件，避免落入 `mouse-yank-register` 的释放复制逻辑。
关闭功能、调整尺寸、切换文档、关闭分屏、失去终端焦点或布局变化时取消捕获。
捕获期间如果文档版本变化也取消本次拖动，防止桶坐标改变造成跳跃。
`editor.mouse=false` 时缩略图继续显示，导航由现有键盘命令完成。

## 7. 标记和主题

- Git 轨道：从已有 diff hunks 聚合新增、修改、删除；纯删除使用当前文档对应边界，包含 EOF 删除。
  同格冲突优先级为删除、修改、新增。不支持 Git 或没有 diff handle 时该列为空。
- 诊断轨道：按源码范围聚合，优先级为 error、warning、info、hint；同格保留最高等级。
- 主光标：在分隔列对应源码行画单独标记，避免被 Git 或诊断覆盖；其他行继续画分隔线。
- 标记使用与代码相同的源码桶映射；视口改变只更新叠加层，不重算源码摘要。
- Git 数据仍在异步计算时，不把旧版本 diff 当成新版本结果。语义以现有 diff/gutter 为准，
  不为本功能扩大工作区信任权限或额外触发 Git 进程。

新增可选主题项，并使用明确的回退：

| 主题项 | 回退 |
| --- | --- |
| `ui.minimap` | `ui.background` 和 `ui.text` |
| `ui.minimap.viewport` | `ui.selection` 的背景色 |
| `ui.minimap.cursor` | `ui.cursor.primary` 或 `ui.cursor` |

Git 与诊断颜色复用既有 `diff.*.gutter` 和 `diagnostic.*` 项。
旧主题不需要修改。无 truecolor 时使用现有终端调色能力；无法准确检测字体是否缺 Braille 字形，
因此通过 `render="blocks"` 让用户手动切换，不声称能自动判断字体支持。

## 8. 缓存、调度和失效

### 8.1 分离源码摘要、几何投影与叠加层

1. 文档级 `MinimapSummary`：源码占用及高亮类别，依据文档 ID、版本、语言/语法代次、Tab 宽度构建。
2. 视图级投影：把摘要压缩到该分屏的宽高和渲染模式；不同分屏可以复用摘要。
3. 叠加层：视口、主光标、诊断、diff；分别按各自变化更新，不因光标闪烁重新生成源码图。

第一版允许编辑后按新版本重建摘要；不要求做复杂的语法增量缓存。
同一源码版本的滚动、光标移动和空闲重绘必须复用缓存。
改变语言或重新载入语法但文本版本不变时，也必须更新语法代次，不能只比较 `Document::version()`。

### 8.2 调度方式

渲染函数只读取已完成摘要并绘制有界网格，不扫描全文、不做同步 I/O。
摘要在现有事件/作业通路中延迟约 150ms 合并编辑请求，按文档版本分片推进。
每片以不超过 128 行、32KiB 源码或约 3ms 为让出目标，先满足行数和字节上限；
3ms 是需测量的调度目标，不能假定单次高亮调用必然可抢占。

由于当前 `Syntax` 不能直接克隆，不把借用的 `Document`/`Syntax` 发送到 `spawn_blocking`。
第一版在编辑器线程分片获取现有高亮，每片结束便释放借用，通过后续 job callback 继续并触发重绘。
遇到大于 8KiB 的单行，只对其有界前缀计算形状，跳过该行语法着色。
如实测高亮查询仍造成明显卡顿，应先降为形状模式；线程化语法快照属于后续优化，不阻塞第一版。

每次继续和发布结果前检查文档仍存在、版本/语言/配置代次匹配、至少一个分屏仍需要该摘要。
编辑、重载、关闭或关闭开关后，旧结果不得覆盖当前状态。只为实际显示缩略图的文档安排计算。

摘要尚未完成时先画准确的视口/光标和空代码背景，导航依据当前文档行数照常工作。
不得为了快速显示而使用行数已不匹配的旧图。可复用同一版本的摘要做新尺寸投影。

### 8.3 资源上限与降级

- 摘要压缩每行颜色段数；缓存上限暂定每文档 8MiB、会话合计 32MiB，超限时淘汰不可见文档优先。
- 超过 50,000 行或 4MiB 文本时改用无语法色的有界抽样轮廓，不遍历全文建立逐行语法摘要。
  每个子像素桶最多均匀取 8 个代表行；仍保留正确行数映射、视口和已有诊断/Git 标记。
- 大文件降级轮廓只承诺近似分布，不承诺显示每一段短代码；导航始终使用真实源码坐标。
- 每行最多扫描 160 个显示列和 4,096 个字符，并遵守分片字节上限；长单行与零宽字符不能拖垮 UI。
- `enabled=false` 立即取消待处理任务并释放本功能缓存；因窄窗口隐藏则暂停该视图任务。
  关闭文档释放相应摘要，关闭/切换视图释放相应投影和拖动状态。

上述预算是工程初值，实施时应根据测量调整并记录；不能把目标数字写成已经达到的性能结果。

## 10. 实施顺序与验收

这是跨配置、几何、渲染、输入和生命周期的中等规模功能，建议按三个可验证阶段实现：

1. **配置与布局**：默认关闭、重载/临时开关、正文宽度一致、窗口太小时隐藏，先保证排版和坐标正确。
2. **缩略图与导航**：共享摘要、点阵与色块、语法色、视口/光标、点击和拖动、取消和资源限制。
3. **标记与兼容**：诊断、Git、折叠/分屏/AI 补全/函数提示回归、真实终端视觉与性能验收、用户文档。

必须覆盖的结果：

- 默认关闭及运行时关闭后，正文矩形、屏幕内容和鼠标位置恢复到原先行为。
- `config.toml` 的最小配置、完整配置、错误字段/值、项目合并、`:config-reload`、`:toggle-option` 均可验证。
- 空文件、短文件、10,000 行文件、超大文件、超长行、中文/emoji/Tab、文件末尾都能正确映射和导航。
- 不同宽高的同文件分屏独立高亮；调整终端尺寸、开关 Git dock 不越界；状态栏和边框完整。
- 软换行、函数/类折叠、多行函数提示和 AI 灰字不改变缩略图的源码总坐标。
- 点击折叠区域能展开并定位；拖动出界、释放、编辑中断、切 buffer、关闭视图/开关不残留捕获状态。
- 缩略图内操作不触发正文拖选、释放复制、粘贴和断点；选择模式与其他选区遵循第 6 节。
- 没有语法、没有 LSP、没有 Git、`--no-default-features` 时仍可用，已有数据缺失时对应标记为空。
- 开启/关闭/导航前后，源文件内容、脏标记和撤销历史不因 Minimap 本身改变。
- 编辑、语言切换、重载、撤销重做后不发布过期摘要；连续重绘不会重新读取全文或启动 Git/LSP 请求。

# AI Git add / commit 设计

日期：2026-11-14。状态：用户已批准设计并授权实现、验证、编译 release、合并推送 master、发布 release 和替换本机 Helix。

独立实现可行性审阅已完成：未发现影响实施计划的未决问题。

## 已确认的目标

在 Helix 内完成“AI 推荐本次暂存文件 → 用户检查并暂存 → AI 生成提交信息 → 用户检查并提交”。沿用原生命令、现有 Git 工具窗口和已有 AI provider。

用户已经选择：AI 推荐要 add 的文件；实际提交前由用户确认；提交信息采用 Conventional Commits；默认中文，可以切换英文。type 和 scope 使用英文，语言选项作用于 subject 和 body。

下文的命令、默认参数、边界及交互细节已作为第一版的实现依据。

## 方案选择

1. 手动暂存，仅让 AI 写 message：工作量小，但不能覆盖用户要的文件推荐。
2. AI 推荐文件，用户确认暂存和提交：所选方案。用户能检查范围，复用现有 Git 工作流。
3. AI 自动拆分并连续提交：需要逐段暂存、分组依赖和失败恢复，不纳入第一版。

第一版提供一次提交。AI 发现不相关改动时，推荐一个有明确目的的文件组，并说明未选文件的原因；不能自动创建多次提交。

## 命令与入口

- `:ai-commit`：打开或聚焦当前仓库的提交工作区，启动文件分析。
- `:ai-commit <意图>`：把其余参数作为可选自然语言意图，例如 `:ai-commit 优化补全响应速度`；不是 shell 命令。
- `:ai-commit-cancel`：取消当前模型请求；不撤销已经完成的 Git 操作，不丢弃手动编辑的 message。
- 现有 Git 操作菜单增加“AI 提交”，与原生命令进入同一组件。不改变 Space g 和已有 Space v 键位。

已有工作区时重复调用先聚焦，不覆盖手动草稿；改变意图通过显式重新分析操作应用。每个工作区只允许一个请求/写操作在运行。

普通暂存、取消暂存、编辑 message 和提交属于 Git 能力，即使 AI 请求失败也能使用。禁用 AI 功能时不发送模型请求；缺少 git feature 时保留可编译的明确错误入口。

## 用户操作

### A. 分析与选择

进入后读取分支、HEAD、暂存区和工作区。分别显示“已有暂存”和“可加入的改动”，提供文件 diff，并区分 staged / unstaged / untracked。

AI 推荐候选文件并解释为什么属于同一个提交。建议只改变候选勾选状态，不执行 add。用户可以增删勾选、看 diff、修改提交意图，或重新分析。

已有暂存区是本次提交的固定起点：默认保留并纳入分析，明确提示“提交会包含全部已有暂存内容”。AI 不能自动排除或撤销它们。需要排除时，用户显式选择“取消暂存该文件”，然后刷新推荐。

部分暂存文件默认仅保留已暂存版本；其未暂存部分显示为单独候选，默认不选。若用户显式勾选加入该文件剩余改动，必须说明这会将该文件的磁盘版本整体暂存，替换它当前的部分暂存状态。

### B. 暂存

用户选择“暂存所选”才写真实 index。操作前重新校验快照、显示要加入的精确路径及整文件暂存语义。第一次选择已构成对当前预览范围的确认，不再叠加一个相同内容的确认弹窗。

仅暂存明确选择的路径，包含删除和重命名所需的旧/新路径；不执行无范围的 `git add .` / `git add -A`。忽略文件不在候选中，也不 force-add。

暂存成功后刷新真实 index，进入 message 生成。暂存失败时重新读取实际 index 并展示现状；不假设失败意味着完全没有写入，也不自动回滚用户或外部程序的暂存内容。

用户也可以只暂存、不提交。已存在暂存内容且没有新候选时，可直接选择“生成提交信息”，跳过暂存。

### C. 生成和编辑 message

提交信息只根据实际的 HEAD → index diff 生成，不能根据磁盘未暂存内容生成。空暂存区不发起 message 请求，禁止 empty commit。

支持的 type：feat、fix、refactor、docs、test、perf、build、ci、chore、style、revert。scope 为可选英文标识，建议模块名或目录名；没有合适范围时使用 `type: subject`。格式如下：

```text
feat(ai): 支持生成函数注释

- 支持 C/C++ 和 Python
- 添加预览与重试操作
```

英文对应 `feat(ai): support function documentation generation`，正文也使用英文。中文正文可以保留 API 名、路径和其他技术标识。

AI 返回结构化 type、scope、subject、body，由编辑器校验和组装。第一版不自动判断或添加 breaking-change 标记；用户可手动编写符合规范的 `!` 和 footer。message 不使用 reST，reST 仅属于函数注释功能。

提交工作区提供“中文 / English”选择。默认来自配置，每次工作区可覆盖，不偷偷修改配置文件。切换语言只更新本次生成选项；已有手动修改的文本保留，用户选择“重新生成”才替换。AI 草稿也由显式重新生成更新，避免切换时意外覆盖。

标题建议简短、目标不超过 72 个显示列，超长提示但不硬截断中文。校验 Conventional Commits 首行、非空 subject、单行标题和合法文本；允许用户手动正文和 footer。type/scope 可修改。没有测试证据时不能写“测试通过”等结论。

手动修改过的 message 不会被异步旧请求覆盖。范围变化后标为“需重新检查”：AI 草稿失效，手动草稿保留；用户需对新的 staged diff 明确选择重新生成或保留手动文本，再启用提交。

### D. 提交

用户检查最终 staged 文件清单、diff 和 message，选择明确的“提交”操作即执行 commit，不再重复确认。首次 Enter 默认只打开文件或编辑 message，不能意外提交；提交按钮/动作必须独立、明确。

只提交真实 index 的全部内容，绝不附加 `-a`，不自动暂存其他文件，不自动 push、amend 或多次 commit。通过受控 UTF-8 临时文件向 Git 提供 message，不拼接 shell 命令。

成功后显示实际 commit hash，刷新状态和日志。未提交的文件继续留在工作区。

## 快照、并发与失败

- 快照绑定仓库根、worktree/git-dir、HEAD 的符号引用和 OID（含 unborn HEAD）、index 条目及模式，以及候选磁盘内容摘要；不是只检查 mtime。
- 读取一个快照时前后校验仓库状态；文件在读取中变化则重试/提示刷新，不把混合时刻的 diff 发给模型。
- AI 结果绑定请求序号、分析快照、模型配置、语言、意图和草稿修订号；过期回调丢弃。
- 暂存前校验 HEAD、index 和选择的磁盘版本，变化就停止并刷新。提交前校验分支、HEAD 和实际 index tree 与最终预览一致。
- 复用现有仓库级操作 guard，防止 Helix 自身的 add/commit/checkout 等写操作重叠。Git 的 index/ref 锁用于各自写入；不能宣称能在最终检查和 Git 启动之间阻止所有外部程序操作。
- 相关未保存缓冲区会明确标记；若该路径涉及本次分析/暂存/提交，必须先保存或排除后刷新。无关未保存缓冲区不阻塞本次操作，不自动保存全仓库。
- 普通分支、初始仓库和 detached HEAD 可用；detached HEAD 要明确展示。存在 unmerged index 或正在 merge/rebase/cherry-pick/revert 时阻止普通 AI 提交流程，指向已有冲突/继续操作入口。
- 正常运行 Git hooks，尊重现有提交身份与签名配置，不绕过失败检查。需要交互的 hook/签名不能卡住编辑器；超时或失败展示诊断并保留草稿。
- hook 可能改变文件、index、message 或 HEAD。执行失败、超时或返回不确定时，检查实际 HEAD/index 并展示是否已有提交；不盲目重复 commit，不自动 reset。成功后以实际提交内容和 message 为准，若与预览不同则明确提示差异。
- 取消仅适用于读取/AI 等待阶段。已经启动的 add/commit 不用 Esc 强杀来假装回滚；保持运行状态直到结束或受控超时，再检查实际结果。
- 关闭工作区取消读取/AI 回调，防止向新窗口写入旧结果；运行中的 Git 写操作由后台 job 持有并报告完成结果。
- AI 故障允许手动选文件、暂存、填写 message 和提交；错误不产生隐藏写操作。

## 模型输入与边界

复用共享 OpenAI-compatible HTTP transport 和 provider 配置，独立启用 `[editor.ai-commit]`；不依赖自动补全开关。发送范围仅为当前仓库有关的文件状态、所需 diff、用户意图和少量近期提交标题作为风格参考；不发送个人全局配置或完整历史。

沿用现有 Git workspace trust 判定；未信任仓库不分析或执行 Git 操作。只在用户显式调用或重新生成时请求模型。分析批次串行执行；运行期间暂停自动补全请求，避免本地模型被抢占。AI 注释和 AI 提交的显式生成不并行，已有显式请求时提示先完成或取消它；Git 写操作与 AI 请求分别维护生命周期。

模型只能引用由后端分配的文件 ID，不能返回可执行 Git/shell 命令或自主路径。输出必须校验 ID、重复项、字段、长度和枚举；差异中的“指令”属于待分析文本。真实路径保留 OsString/字节语义，显示文本与执行路径分开；终端控制字符转义。

分批完整分析可容纳的文本 diff，先形成逐文件摘要，再进行候选推荐；实际 staged message 生成也需要覆盖全部暂存内容。默认每个 AI 输入包的 diff/数据字节预算为 4096，输出预算 768 tokens，服务拒绝上下文长度时降低批大小并明确报错。模型上下文不同可配置，不能把字节预算宣称成精确 token 计数。单文件超预算不截断后假装完整理解：标记“需手动检查”，提供本地完整 diff。

默认候选最多 64 个文件；超出时先让用户缩小范围，不只分析前 64 个却给出“全仓库推荐”。文件计数包含已经暂存的文件。二进制、子模块指针、符号链接、超大文件和敏感路径只展示元数据，AI 不自动选入；用户仍可手动加入并检查 Git 支持的本地 diff/状态。密钥、凭据和 .env 等常见敏感文件默认不向模型发送内容；该规则只是保守启发式，不能保证识别所有秘密。

只要 staged 中有模型未完整分析的内容，自动 message 标为不完整建议，不能伪装覆盖全部变更；提交仍可由用户补充并明确保留手动文本后完成。

## 建议配置

```toml
[editor.ai-commit]
enabled = true
language = "zh-CN"        # 或 "en"
timeout-ms = 30000        # 每次模型调用
max-tokens = 768
max-input-bytes = 4096    # 每批数据预算，不是 token 数
max-files = 64
```

新安装默认 enabled=false，明确配置后启用；中文为功能默认语言。预算对单次请求生效；批量分析展示进度，可随时取消。单次用户分析最多 64 批模型调用，达到预算就停止并显示未分析范围，不后台无限重试。文件推荐和 message 生成分别计数，显式重新生成重新开始。

## 模块划分与实现选择

- `helix-vcs`：状态和 staged/worktree diff、快照校验、路径级 stage/unstage、提交执行与结果核对，复用 Git executable 和现有可信仓库/超时机制。
- `helix-view`：配置、语言、会话状态、快照标识和 message 草稿修订。
- `helix-term`：typed commands、现有 Git 面板中的提交工作区、异步 AI 分析及结构化响应校验，复用共享 AI transport。
- 当前 WorkingTree diff 不能区分生成 message 所需的 staged 内容，需增加明确的 index diff 读取接口。
- 不引入 agent framework 或新依赖；所有 Git 参数通过参数数组传递，读 diff 禁用 external diff/textconv，普通写操作尊重受信任仓库的 Git 配置。

具体布局比例、内部类型名、缓存结构、精确快捷键和批调度算法由实现者决定；必须保持底部停靠/全屏切换、小终端可用、键盘可达和现有键位兼容。无需另开外部 Git 应用。

## 验收与范围

只在临时真实 Git 仓库验证写入行为，不对用户仓库进行测试 commit。覆盖：

1. AI 推荐不修改 index/文件/HEAD；取消和过期响应没有写入。
2. 精确路径暂存：中文、空格、前导连字符、删除、重命名，已有暂存、部分暂存和无初始提交。
3. message 只反映 index，文件推荐与实际提交一致；中文/英文切换、手动编辑、范围变更和刷新不丢草稿。
4. HEAD/index/文件并发变化使建议失效，Helix 写操作互斥，外部竞争得到可见诊断。
5. hook 成功/失败/修改文件及 message、签名失败、超时后检查状态，重试不重复创建提交。
6. 模型错误、无效 JSON、未知文件 ID、长上下文、二进制/敏感/超大文件、预算耗尽都有明确状态和手动路径。
7. git feature 关闭时可编译，现有 Git 工具和 AI 注释/补全不回归；运行有针对性的 Rust 单元/集成测试、格式检查及实际 Helix 交互验证。

第一版产品流程不含自动 push、自动拆分提交、逐段暂存、自动修改源代码、amend、rebase 或 AI 冲突解决。用户已另行授权本次功能开发完成后的编译、合并推送、发布和本机替换；这不代表产品在执行 :ai-commit 时自动 push。

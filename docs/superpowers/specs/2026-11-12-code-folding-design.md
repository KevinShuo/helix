## 2. 用户目标与第一版范围

目标是缩短长函数在屏幕上占用的空间，方便浏览与定位，同时随时展开继续编辑。
截图涉及 Python 和 C++，第一版优先覆盖这两种语言。

第一版的完成标准：

- 保留完整函数签名；多行参数和 Python 装饰器继续显示。
- 函数体收起后显示单个 `…`；C++ 的闭合 `}` 继续可见。
- 行号旁显示展开/折叠标记，既能键盘操作，也能鼠标点击。
- 提供当前函数的折叠、展开、切换，以及当前文档的全部折叠、全部展开。
- 搜索、定义跳转、诊断跳转和跳转历史能自动展开目标所在区域。
- 同一文件在两个分屏中的折叠状态互不影响，切换 buffer 后保留各自状态。
- 保存、复制、LSP、格式化和撤销重做继续针对真实文档工作。
- 已有函数引用数、Git 作者提示、AI 行内补全和底部 Git 窗口正常工作。

第一版先处理函数/方法及嵌套函数。类、循环、条件块、注释、imports、任意选区、
按层级折叠、重启后恢复状态、默认自动折叠和无语法树时的缩进回退留到后续。
Rust 函数折叠适合作为后续扩展，便于在 Helix 自身源码中使用。

## 6. 核心设计

### 6.1 函数范围与折叠状态分开

- `FoldCandidate`：由语法树得到的可折叠函数，包含声明锚点、隐藏字符区间和类别。
- `FoldCandidates`：文档级候选缓存，绑定文档版本和查询配置；编辑、重载或语言变化后失效。
- `FoldState`：用户在某个视图中关闭的区间，建议放入 `Document` 内的 `ViewData`。
- 所有范围统一使用 Helix 的字符索引；Tree-sitter byte offset 必须通过 Rope 转换。
  使用半开区间 `[start, end)`，不能混用字节、UTF-16、文档行和屏幕行。
- 关闭一个父函数时保留子函数的关闭状态；输出给排版器的有效折叠集合只包含最外层区间。
  展开父函数后恢复子函数原有状态。重复区间合并，非嵌套的交叉区间丢弃。

把状态放在 `(DocumentId, ViewId)` 下，可以避免一个分屏折叠后另一个也跟着折叠，
也便于沿用文档的视图清理和编辑映射机制。

### 6.2 显示边界

- Python：保留装饰器和完整签名直到函数声明的冒号；隐藏冒号之后的函数体，
  不吞掉函数结束后的分隔换行或下一条顶层语句。
- C++：保留完整声明与函数体开头的 `{`，隐藏 `{` 和对应 `}` 之间的内容，保留 `}` 及其后缀。
- 通过语法结构确定冒号/花括号，不用简单字符串搜索或只看缩进。
- 只对跨行且有有效内容的函数体提供折叠；单行、空函数体和无可靠边界的错误节点不折叠。
- 第一版占位符使用单个 `…` grapheme；隐藏行数等多字符标签作为后续增强。
- 原始行号保持真实文件位置；收起后行号自然跳跃，不能重新编号。

例如 C++ 显示为 `void assemble(int train[]) {…}`，Python 显示为 `def main():…`。
这些只是视图效果，Rope 与保存的文件必须完全不变。

### 6.3 排版与坐标必须共享一种折叠表示

建议在 `TextAnnotations` 增加隐藏区间/折叠注解，并让 `DocumentFormatter` 消费。
API 名称由实现者决定，但必须满足：

1. 迭代器遇到折叠区间时输出占位符，并直接跳到区间末尾，而非遍历全部隐藏字符。
2. 明确区分占位符的屏幕宽度、消耗的文档字符数和跨过的文档行数。
   当前 `GraphemeSource::Document { codepoints }` 本身不足以表达所有行为，需要一并设计。
3. 保证 `char_idx`、`line_idx`、高亮游标、注解游标和检查点在跳过区间后同步。
4. 排版、文档到屏幕、屏幕到文档、软换行和滚动共享同一份有效折叠集合。
5. 从隐藏区间内部创建排版器/恢复视口时，先将起点规范到可见锚点，不能泄漏函数体。
6. 点击占位符映射到可见声明锚点；占位符不是可编辑的源字符。
7. 同一屏幕行可能包含声明行和原始闭括号行；侧栏使用该屏幕行起始的声明行号。

不能仅在终端绘制时跳过几行，否则坐标计算、光标和鼠标点击会与显示不一致。

### 6.4 移动、选区与主动折叠

第一版采用以下明确规则：

| 操作 | 推荐行为 |
| --- | --- |
| `h/l/j/k`、按屏幕行移动和翻页 | 把关闭区域视为占位块，跨过隐藏文本，保持函数关闭 |
| 搜索、单词/语法移动、LSP 跳转、诊断和历史跳转 | 若实际目标落入隐藏区间，展开所有包住目标的父折叠后定位 |
| 主动折叠当前函数 | 从当前光标选择最内层候选；若主光标在函数体，先把主选区收为声明处光标再折叠 |
| 存在其他光标位于待折叠函数体 | 不关闭该候选，给出状态提示，避免藏住其他编辑位置 |
| 全部折叠 | 关闭当前文档的函数候选；跳过包含任意光标的候选，保留当前编辑位置可见 |
| 展开当前函数 | 展开光标所在声明对应的关闭区域；嵌套时优先展开当前可见的外层 |
| 跨越折叠的选区 | 保持真实字符范围，复制、删除、替换仍覆盖其中的真实文本 |
| 在边界插入或编辑隐藏内容 | 先展开受影响区域，再按现有编辑规则修改 |

自动展开应在统一设置选区/应用事务路径兜底，覆盖全部入口。
普通移动命令则应先计算跨过折叠后的可见位置，再交给该兜底；
否则按一次方向键就会把刚收起的函数重新展开。
跨区域编辑按真实选区工作，不能为了显示折叠而截断用户选区。

### 6.5 编辑、撤销与生命周期

`Document::apply_impl` 当前会更新所有选区和所有 `ViewData` 的视口锚点。
建议在这里用同一份 `ChangeSet` 更新每个视图的关闭区间和声明锚点，
再验证范围合法性、展开受编辑影响的区域并使候选缓存失效。

- 在函数前插入/删除文本：区间随编辑移动，仍然对应原函数。
- 改动函数体、边界、括号或冒号：保守展开受影响区域，重新解析后再提供候选。
- 删除整个函数或失去合法边界：移除相应状态，不能留下越界或折叠下一函数的旧范围。
- 统一设置选区时检查所有光标；纯选区事务也必须走自动展开逻辑。
- 撤销、重做、外部重载、语言变化、关闭视图/文档都要覆盖；整文件重载可保守清空状态。
- 折叠/展开自身是视图操作，不设置文档 modified，不递增文本版本，不进入文本撤销栈。
- 原始编辑路径已逐事务更新范围时，不要再在 `View::sync_changes` 中重复映射。
  这里已有跳转历史的懒同步机制，两种机制必须明确区分。

### 6.6 其他功能兼容

- **高亮**：依据排版后实际可见源码区间计算语法、覆盖层和彩虹括号范围，
  验证巨大折叠后的第一行仍正确着色。避免每帧扫描整段隐藏源码。
- **函数提示**：声明处的引用数/Git 作者继续显示。若其原始行尾锚点落入隐藏区间，
  在视图注解层投影到可见声明尾部；LSP 和 Git 查询仍使用真实源码坐标。
  隐藏函数不产生可见提示，候选请求的可见性筛选也要考虑折叠变化。
- **inlay hints / 行内诊断 / 颜色提示**：隐藏体内的注解不参与排版或增加虚拟行。
- **AI 行内补全**：折叠改变可见上下文时清理过期预览；展开后按原调度重新请求。
  折叠不能接受补全或改动真实文本。
- **Git 窗口**：底部停靠、全屏切换和终端 resize 后重新计算视口，保持光标可见。
- **性能**：按文档版本缓存候选；渲染仅查询有序有效关闭区间，定位后直接跳过。
  不在每次按键或每个光标坐标查询时重新扫描全部语法树。

## 7. 命令、侧栏与配置建议

| 推荐按键 | 命令 | 含义 |
| --- | --- | --- |
| `za` | `toggle_fold` | 切换当前函数 |

## 9. 验证清单与命令

必须覆盖的结果：

| 场景 | 通过标准 |
| --- | --- |
| 折叠/展开后保存 | 文件字节不变，文档不因视图操作变脏 |
| 多行签名与闭括号 | 签名不丢行，C++ `}` 及后缀仍显示 |
| 嵌套、相邻和 EOF 函数 | 展开父函数恢复子状态，无越界；保留末尾换行语义 |
| LF / CRLF / 无末尾换行 | 隐藏范围不切断 CRLF，不吞掉下一语句 |
| 中文、emoji、Tab | 字符/字节/屏幕宽度映射正确 |
| 搜索、诊断、定义和历史跳转 | 目标自动可见，光标位于真实源码位置 |
| 方向移动、软换行、鼠标、翻页 | 不陷入隐藏文本；正反映射保持一致 |
| 编辑、删除函数、撤销重做 | 范围正确移动或失效，不错折叠其他函数 |
| 多光标与跨区间复制/删除 | 无隐藏编辑光标；选区作用于完整真实文本 |
| 两个分屏与 buffer 往返 | 状态独立，并随当前文档变化正确更新 |
| 函数提示、AI 补全、行内诊断 | 声明提示保留，隐藏注解不泄漏，补全不被意外接受 |
| Git 窗口及 resize | 可见区域和折叠坐标同步调整 |
| 大文件 | 跳过大函数时不逐字符扫描隐藏文本；记录固定样本的耗时和内存对比 |

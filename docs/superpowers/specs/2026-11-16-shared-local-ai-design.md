# 多个 hx 实例共用本地 AI 模型

## 目标与现状

用户要求多个 hx 进程共用本地模型，并继续使用现有 9B 补全、27B 显式生成及自动恢复补全的工作流。

当前 `server.rs` 的子进程归单个应用所有，应用退出会终止子进程。其他应用仅通过模型别名检查复用已有 HTTP 服务；`server/pool.rs` 的临时模型租约拒绝复用外部持有的常驻模型。这导致第二个编辑器不能切换到 27B，且第一个编辑器退出会影响其他实例。同时启动还存在检查端口与实际启动之间的竞争。

## 方案比较

1. 只修复启动重试和模型复用：改动较小，但不能安全地跨进程卸载 9B、切换 27B，也无法解决首个编辑器退出导致服务中断。
2. 手动运行独立 llama.cpp 路由服务：依赖外部服务的配置和生命周期，会改变当前 managed provider 和按需切换的使用方式。
3. **建议：hx 自动启动并连接一个当前用户独享的模型管理辅助进程。** 管理器统一拥有 llama-server、协调推理请求与显存切换。用户继续使用原配置，无需手动启动服务。代价是新增本地进程协议和生命周期管理。

用户已回复“直接做”，确认按方案 3 实施。

## 对外行为

- 多个 hx 连接同一个管理器；相同模型配置只加载一份。
- 无论哪一个 hx 最先启动或退出，其余实例继续使用模型。
- 本次明确采用全局串行的模型请求调度。完成补全请求后，显式生成请求可以独占模型并切换到 27B；其他实例的补全等待并可取消，不因模型暂时切换而报端口冲突。
- 显式生成完成、取消或发起者退出后恢复 9B，再处理等待的补全。排队请求先到先服务，自动补全的过期请求沿用现有取消机制，不实现优先级插队。
- 模型推理期间最多保留一套管理器持有的活动模型，兼容本机 24GB 显存。不同 hx 配置了不同模型时，按有效请求切换，不通过修改其他实例的配置解决冲突。
- 最后一个客户端断开后等待 10 秒，再退出管理器并释放模型；该期限内重连可复用模型。客户端异常退出也应释放请求租约。
- 保留现有配置字段、各模型 endpoint 和外部服务的使用方式。不接管和终止未由管理器启动的服务；对冲突配置返回明确错误。

## 实现边界

- 新增 hx 内部辅助进程入口及管理模块；辅助进程独立于启动它的编辑器生命周期，不显示控制台窗口。
- 使用操作系统级互斥选出唯一管理器，锁随进程终止释放；不能只靠 PID 文件判断存活。多个 hx 同时启动时等待同一个管理器就绪。
- 管理器监听本机随机控制端口，连接信息与随机认证凭据放在用户私有缓存目录。协议有版本标识、长度限制、鉴权和有限等待；不在日志中写出凭据。不同协议版本明确失败，不能杀死旧版本管理器及其正在服务的实例。
- 连接注册编辑器生命周期及其实际启用的 provider。请求单独持有可取消的控制连接租约；控制连接断开即取消排队或释放当前租约。请求租约包围真正的 HTTP 推理，而非仅包围模型就绪检查。
- 初次连接预热该客户端的补全模型；已有其他活动模型时登记常驻偏好，避免新编辑器启动打断正在执行的请求。恢复补全使用当前显式生成发起者的补全 provider；其他客户端的不同模型按其下一次请求切换。
- 管理器验证完整启动配置和模型路径，复用不能仅凭模型别名；启动设置发生变化的请求在当前请求结束后重新加载。模型身份不符时不发送源代码。
- 自动补全和 Doc、Commit、Test、Merge 的 managed 请求全部通过统一租约路径。网络 provider 继续直接请求。原有外部服务仅保留已有安全复用语义，不参与管理器控制的显存切换。
- 请求等待与加载继续服从调用者的取消和预算；排队等待单独计入现有启动预算，推理预算在就绪且获得租约后开始。管理器或模型异常退出使当前请求明确失败，后续请求可重新连接或拉起管理器，不无限重复用户生成操作。
- 保留原有单应用池的测试价值，调整现有“外部持有”测试以区分可信管理器持有和未知外部进程。

## 验收

先增加会失败的进程级回归，再实施。使用独立缓存目录、临时端口和测试服务，不干扰用户正在编辑的 hx。

1. 两个独立 hx 客户端同时启动，仅出现一个管理器和一份模型；两个客户端均可补全。
2. 先启动者退出后，另一个客户端仍可补全；最后一个客户端退出后模型被释放。
3. 两个实例依次发起 27B 生成均成功，切换期间补全可取消，生成后两个实例恢复补全。
4. 发起者在排队、模型加载、推理和恢复过程中取消或异常退出，其他客户端不会永久阻塞，也不会残留重复模型。
5. 管理器崩溃、模型崩溃、启动竞争、配置不一致及外部端口占用都有确定的恢复或明确错误。
6. 现有 AI 回归通过；真实 GPU 验证两个独立 hx 实例共用 9B，并执行 9B → 27B → 9B。
7. Release 构建通过，备份并替换本地 hx；不终止用户现有编辑器进程，交付时说明旧实例需重新打开。

## 留给实施者的选择

协议编码、模块划分、缓存文件名称、测试辅助进程的具体组织方式由实施者决定。先保证多进程生命周期和取消行为；本次不做并行 GPU 推理、跨用户共享、系统服务安装或远程推理管理。

## 实施平台

本机 Windows 使用 Job Object 保证管理器崩溃时模型同时退出。Linux 使用 parent-death signal；本次未在 Linux 实机验证。macOS/BSD 缺少对应的已实现进程保护，继续使用原有模型生命周期管理，不启用共享辅助进程。

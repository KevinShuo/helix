# `.gitignore` 内置模板生成器设计（方案 A）

日期：2026-11-16。状态：用户已批准方案与完整设计，并授权开始实现。

## 1. 意图与已确认范围

用户希望在 Helix 内为项目创建 `.gitignore`：根据项目类型自动识别并推荐内置模板，支持常见语言、构建工具和通用模板的组合，生成后允许检查、修改，再由用户保存。用户已选择方案 A：只识别项目根目录，不扫描子项目。

体验目标：用户执行一次命令，确认推荐的模板组合，即可得到可编辑的 `.gitignore` 草稿。模板随程序提供，生成过程离线、结果稳定。

以下具体交互、模板清单和边界处理是本设计的建议，并非用户逐项指定。

## 2. Approaches：方案与取舍

| 方案 | 做法 | 取舍与结论 |
| --- | --- | --- |
| A：根目录识别 + 模板组合 | 检查根目录标志文件，推荐内置模板，用户调整后生成 | 用户已选择。扫描成本可控，规则来源容易说明；根目录没有标志文件的子项目需要手动补选模板 |
| B：多项目工作区识别 | 同时识别 `packages/*`、`apps/*` 等目录中的项目 | 可以覆盖混合仓库，但需要额外设计扫描边界、子目录作用路径和冲突处理；后续再考虑 |

首版使用独立的模板多选组件和编译进程序的模板资源。现有 `Picker` 是单选文件预览器，不为此改变其公共行为。生成结果沿用普通命名缓冲区的编辑与保存机制。

## 3. 目标与非目标

必须支持：

- 从当前编辑上下文确定目标项目根目录，明确展示 `.gitignore` 的绝对目标路径。
- 根目录标志文件识别、多模板推荐、搜索和手动勾选。
- 用户看得出每个推荐的依据，例如 `Cargo.toml`。
- 生成命名缓冲区，保留原有文档和修改；仅在用户保存时写盘。
- 已有 `.gitignore` 和同路径缓冲区保护。
- 无网络、无 AI、无外部 Git 命令依赖；没有执行 `git init` 也可使用。

首版不做：子项目扫描、解析依赖以识别具体框架、在线拉取模板、自定义模板配置、批量创建子目录 `.gitignore`、更新或合并已有规则、改写全局 Git 忽略文件、自动暂存或提交。

不可接受的结果：覆盖已有内容、丢失未保存编辑、按当前工作目录误操作另一个仓库、生成过程执行项目代码、默认忽略源代码或锁文件、按字母排序规则而改变例外语义。

## 4. 入口与主流程

- 命令：`:gitignore`，无参数、无强制覆盖变体。
- 静态命令：`gitignore`，用于自定义键位。
- 默认快捷键：`Space v i`，Git 菜单显示 `Generate .gitignore`。目前 `i` 未占用。
- 两种入口共用同一个处理流程，不要求先打开 Git 面板。

流程：

1. 捕获当前上下文，确定固定目标目录和 `.gitignore` 路径。
2. 如果同路径缓冲区已经存在，直接切换到它；否则，如果磁盘文件存在，按普通文件打开。两者都不进入模板生成流程。
3. 若目标不存在，在后台检查根目录标志文件，打开模板多选组件。
4. 自动勾选识别出的项目模板，显示证据；用户可以取消推荐或添加其他模板。
5. 用户确认生成后，再次检查目标和同路径缓冲区，读取已编译的模板并组合文本。
6. 打开目标命名缓冲区，通过普通编辑事务插入完整内容，标记为已修改，光标位于首行，保持 Normal 模式，关闭选择组件。
7. 状态提示：`Generated .gitignore from N templates; review and :w to save`。用户自由修改并通过 `:w` 保存。

取消选择界面不产生文件或草稿缓冲区。生成后的放弃、撤销、关闭和保存均沿用普通编辑规则；保存后的再次执行只打开已有文件。

## 5. 目标目录与上下文

### 5.1 起始目录

复用 `Editor::git_context_path()`：普通文档使用其父目录；无路径缓冲区使用编辑器当前工作目录；合并草稿使用其绑定的工作树目录。无可用编辑上下文时提示错误。

### 5.2 根目录判定

1. 从起始目录向上检查最近的 `.git` 标志。`.git` 可以是目录或普通文件，后者覆盖常见 worktree 和 submodule 布局；只用其所在目录，不读取 `.git` 内容或 Git 配置。
2. 找不到 `.git` 时，使用 `helix_loader::find_workspace_in(start)` 的结果，包括 `.helix`、`.jj`、`.svn` 标志；没有任何标志则以起始目录作为目标目录。
3. 非 Git 目录明确标注 `No Git repository detected`，仍允许生成；不自动初始化仓库。

这是目录标志识别，不是仓库有效性验证。最近的 `.git` 决定工作树边界，嵌套仓库不会跳到外层仓库。仅有 `GIT_DIR` / `GIT_WORK_TREE` 等特殊配置且目录树中没有 `.git` 标志的布局不做专门解析，按非 Git 目录处理。

不直接用 `find_workspace_in` 代替 Git 根定位，因为嵌套 `.helix` 可能比 `.git` 更近。不复用 `GitRepository::open`，因为本功能无需读取 Git 配置或执行 Git 操作，也不应为此新增信任授权要求。普通文档打开和保存的既有信任策略仍然适用。

生成会话固定目标绝对路径。识别完成或确认生成时，不根据当时活动文档重新计算路径。只规范化已有的目录部分；不存在的 `.gitignore` 不要求完整 canonicalize。路径比较复用既有平台约定，Windows 忽略大小写。

## 6. 根目录识别规则

只检查目标根目录本层的标志项，不递归，不读取配置文件内容，不扫描源代码扩展名，不跟随标志文件的符号链接。一个模板命中多个标志时仍只推荐一次，并记录全部命中依据。

| 根目录标志文件 | 推荐模板 ID | 说明 |
| --- | --- | --- |
| `Cargo.toml` | `rust` | Rust 构建产物 |
| `package.json` | `node` | JavaScript / TypeScript 的 Node 工具链；首版不细分 React、Vue、Next.js |
| `pyproject.toml`、`requirements.txt`、`setup.py`、`setup.cfg`、`Pipfile` | `python` | Python 缓存、虚拟环境和构建产物 |
| `go.mod` | `go` | Go 测试、覆盖率等生成物 |
| `pom.xml` | `java`、`maven` | Java 与 Maven 组合 |
| `build.gradle`、`build.gradle.kts`、`settings.gradle`、`settings.gradle.kts` | `java`、`gradle` | JVM 常见构建产物，不以源码语言做进一步判断 |
| `CMakeLists.txt` | `cpp`、`cmake` | C/C++ 产物与 CMake 缓存 |
| `*.sln`、`*.slnx`、`*.csproj`、`*.fsproj`、`*.vbproj` | `dotnet` | .NET 生成物；只匹配本层普通文件 |

明确不凭 `Makefile` 推断 C/C++，因为它不能可靠代表项目类型；C/C++ 模板始终可手动选择。`.idea`、`.vscode`、宿主操作系统不触发自动勾选，避免把个人偏好当作团队规则。

没有识别结果：显示 `No project type detected; select templates manually`，全部模板仍可搜索和选择。多个项目类型同时命中：默认全部勾选。不会因为缺少对应输出目录而取消推荐，例如没有 `target/` 仍推荐 Rust。

识别在后台任务中完成；目录枚举至多消费 4096 个本层目录项，用于 .NET 扩展名匹配。固定名称的标志检查独立完成，不受枚举顺序影响。超出上限时保留已知结果，并显示识别不完整、可手动补选的提示。标志不存在属于正常未命中；权限或 I/O 错误明确显示“部分识别失败”，不伪装成完整未命中。根目录本身不存在或不可访问则终止流程。

## 7. 模板目录与默认选择

首版目录固定为以下模板；模板 ID 稳定且唯一。

| 类别 | 模板 ID | 初始选择 |
| --- | --- | --- |
| 语言 / 工具链 | `rust`、`node`、`python`、`go`、`java`、`cpp`、`dotnet` | 根据第 6 节识别结果勾选 |
| 构建工具 | `maven`、`gradle`、`cmake` | 根据第 6 节识别结果勾选 |
| 操作系统 | `windows`、`macos`、`linux` | 默认不选；所有平台都能选择 |
| 编辑器 | `vscode`、`jetbrains`、`vim`、`emacs` | 默认不选 |
| 通用 | `temporary`、`dotenv` | 默认不选 |

模板原则：

- 语言模板只包含该生态常见的缓存、依赖目录、编译和测试产物。构建工具模板尽量不重复语言模板的职责。
- 不忽略 `Cargo.lock`、`package-lock.json`、`yarn.lock`、`pnpm-lock.yaml`、`poetry.lock`、`Pipfile.lock`、`uv.lock`、`go.sum` 等锁定文件。
- 不使用 `*.json`、`*.toml`、`*.yaml`、整个隐藏目录等过宽模式；不忽略源码、测试、项目配置和构建工具 wrapper。
- 项目专属的根输出目录按需要使用 `/target/`、`/build/` 等根锚定规则，避免把同名源码子目录一起排除。依赖、缓存等是否递归匹配按各模板的明确用途决定。
- `temporary` 提供常见临时或备份后缀；编辑器专属交换文件放入对应编辑器模板。默认不选，因为临时文件也可能是测试数据。
- `dotenv` 包含 `.env`、`.env.*`，随后明确放行 `.env.example`、`.env.sample`、`.env.template`。描述注明只保留这些约定的示例名，其他示例文件需用户补充放行。不会读取环境文件内容。
- `vscode` 和 `jetbrains` 的描述注明可能涉及团队共享配置，只有用户主动选择才应用。各自的具体共享文件例外在模板注释中写明。

模板可参考 `github/gitignore`，但不直接把全部上游内容当作默认规则。随实现选择一个固定上游 commit，记录 URL、commit、路径和本地裁剪说明；涉及复制的模板附带上游许可。当前上游许可为 CC0-1.0，记录在模板来源说明中。

模板随二进制通过 `include_str!` 编译提供，资源放在 `helix-term/src/gitignore/templates/`，不增加运行时目录和发布包拷贝要求。新增模板需要修改代码中的目录项、资源和对应测试，不开放外部路径加载。

## 8. 模板选择交互

采用专用模态组件，沿用现有终端 UI 的搜索、列表和主题习惯，不修改通用 Picker 的单选语义。首版用一列列表，不增加实时规则预览窗格；生成后的普通缓冲区承担完整检查与编辑。

组件展示：目标绝对路径、项目识别状态、搜索输入、模板列表、当前模板描述和识别依据、已选模板数、操作提示。列表项展示勾选状态、模板名称、类别和 `detected` 标签。推荐项排在前面，其余按固定类别和目录顺序排列。

后台识别期间显示加载状态，只启用取消；完成后一次性初始化推荐与选择集合，再启用搜索、勾选和生成。不会在用户开始选择后异步改变其选择。根目录定位也可放在这一可取消的后台阶段；目标一经确定即固定。

| 操作 | 行为 |
| --- | --- |
| 输入文字 / Backspace | 搜索模板名称、ID、类别和别名，不改变已选集合 |
| 上下方向键、`Ctrl-n` / `Ctrl-p` | 移动高亮项 |
| `Tab` | 勾选或取消高亮模板，不关闭组件 |
| `Enter` | 根据整个已选集合生成，不仅是当前高亮或筛选可见项 |
| `Esc` / `Ctrl-c` | 取消，保留原有编辑状态 |

空格属于搜索文本，不作为勾选键。零匹配结果时移动和 Tab 无效果；已有选择仍能生成。零选择时 Enter 保持组件打开并提示 `Select at least one template`。取消推荐后，继续搜索和移动不会自动重新勾选。

搜索结果不会因勾选而跳动。窗口变窄时目标路径和说明可截断，但保留模板名称、勾选标志、数量与操作提示；极小窗口给出明确提示并始终允许 Esc 退出。长路径在生成后的普通缓冲区仍可查看，不影响真实目标。

## 9. 内容组合与语义

- 先按模板 ID 去重，按固定目录顺序组合；结果不依赖点击先后、搜索顺序或识别完成顺序。
- 每个模板是完整的有序规则块：保留内部注释、忽略规则和 `!` 例外顺序。
- 不排序规则行，不做跨模板或模板内部的规则去重，不计算语义化的等价模式。重复行可读且可保留，避免删掉一次后置重复规则而改变已有例外的最终效果。
- 各块之间用一个空行分隔，并使用 `# --- Rust ---` 一类标题；顶部仅写生成来源和模板 ID，不写时间戳、绝对目录或机器信息。
- 生成文本使用 LF 并以单个换行结尾；保存沿用编辑器正常的编码、换行和保存流程。
- 模板内保持 `/` 路径分隔符，Windows 不替换为反斜杠。
- 首版模板不提供任意组合的语义推断。模板来源审查与组合测试负责常见组合，最终文本由用户确认。

例如 Rust + macOS 的草稿结构：

```gitignore
# Generated by Helix; templates: rust, macos

# --- Rust ---
/target/
# ... the remaining reviewed Rust rules ...

# --- macOS ---
.DS_Store
# ... the remaining reviewed macOS rules ...
```

此示例只说明分段方式，不替代完整模板内容。

## 10. 已有内容、竞争与失败处理

| 状况 | 行为 |
| --- | --- |
| 同路径缓冲区已打开，包括未保存的新文件或空缓冲区 | 切换到该文档，不重新生成、不替换、不重载；提示已有缓冲区 |
| 磁盘已有普通 `.gitignore`，包括空文件 | 按正常文件打开；提示已有文件；不追加规则 |
| `.gitignore` 是目录、符号链接（含悬空链接）或其他特殊文件 | 提示路径类型错误并停止，不跟随链接 |
| 选择过程中其他程序创建目标文件 | 确认生成时发现后按已有文件处理，不注入所选模板 |
| 选择过程中其他操作打开同路径文档 | 确认时复用该文档，不再创建第二个缓冲区 |
| 选择过程中目录被删除、变成文件或不能访问 | 报错，不创建草稿文档或目录 |
| 模板资源或目录定义异常 | 在修改文档前报错，保留选择界面；内置资源在测试中检查 |
| 用户关闭组件后后台检测才返回 | 通过会话 ID 丢弃结果，不重开组件、不改变文档 |
| 从生成到 `:w` 之间目标被外部创建或修改 | 使用编辑器既有外部修改 / 保存冲突保护；不得引入自动强制保存 |

处理目标时先查同路径文档，存在时只切换文档，不读取或跟随磁盘目标；没有同路径文档时，才用不跟随链接的元数据判断路径类型。此后只允许普通文件或缺失路径进入相应分支。Windows 路径大小写差异不能导致重复文档。

生成阶段所有必要校验、模板组合都在文档变更前完成；打开缺失路径后的插入作为一个可撤销事务。正常保留原文件及其未保存内容；空白 scratch 的替换遵循编辑器既有策略。

实现计划须专门覆盖最后校验到文档建立之间的竞争：不能在 `Editor::open` 返回后无条件注入模板，因为此调用可能已经读取刚被外部创建的文件。在模板插入前重新判断目标是否出现或同路径文档是否被复用；发现目标出现时按已有文件处理，保留其内容。草稿建立后的保存使用既有 mtime 冲突保护，仍具有普通文件保存的同等局限；本功能不引入对其他进程写入的原子排斥，也不扩展为通用保存协议改造。

保存前一律不写文件、不创建目录；不改变 Git 索引，也不删除已跟踪文件。`.gitignore` 不会使 Git 已经跟踪的文件自动停止跟踪，说明文档中明确这一点。

## 11. 代码划分与现有实现衔接

| 位置 | 责任 |
| --- | --- |
| `helix-term/src/gitignore.rs` 及同名子目录 | 模板目录、标志检测、根目录解析、确定性文本组合；保持规则部分易单测 |
| `helix-term/src/gitignore/templates/` | 编译内置的 `.gitignore` 文本和来源 / 许可说明 |
| `helix-term/src/ui/gitignore.rs` | 搜索、多选、目标和识别状态、取消与生成的会话管理 |
| `helix-term/src/commands.rs` | 注册静态入口和上下文捕获，启动组件 |
| `helix-term/src/commands/typed.rs` | 注册 `:gitignore`，委托同一入口 |
| `helix-term/src/keymap/default.rs` | `Space v i` 入口 |
| `helix-term/src/ui/mod.rs`、终端 crate 模块声明 | 挂接模块 |
| `helix-term/tests/` | 用户流程与缓冲区 / 磁盘副作用验证 |
| `book/src/` 和命令生成文档 | 用户用法、模板范围、已有文件行为和限制 |

核心数据概念：`TemplateId`、`Template`（名称、类别、说明、搜索别名、有序文本）、`Detection`（模板 ID 与标志依据）、`GenerationSession`（会话 ID、固定目标路径、选择集合、搜索和光标状态）。具体 Rust 类型和模块拆分留给实现者。

`open_new_file` 当前会拒绝同路径已有文件和缓冲区，并且进入 Insert 模式，不能原样作为所有分支的实现。生成器可以复用其中的路径保护思路，但已有文件分支需要明确复用文档；新草稿需要普通命名缓冲区和一次编辑事务。无需新增 Helix 全局通用“文件模板”系统，不修改 Git 面板操作枚举，也不新增依赖。

后台任务只读目录元数据。组件按会话 ID 接收结果，退出时取消任务或忽略晚到结果。该能力不以 `git` feature 开关为前提；禁用 Git 功能的构建仍能按目录标志生成文本。

## 12. 验收与验证

1. Rust 项目中执行 `:gitignore`，Rust 默认勾选且显示 `Cargo.toml`；手动添加 macOS 后生成包含两个分段的已修改文档，磁盘上仍无新文件；`:w` 后内容与编辑结果一致。
2. 根目录同时包含 `package.json` 和 `pyproject.toml` 时同时推荐 Node、Python；只有 `apps/web/package.json` 时不推荐 Node，仍可手动选择。
3. Maven、Gradle、CMake 命中组合正确；任一标志只产生一次模板选择；没有构建产物目录也可推荐。
4. 非 Git 项目、scratch、嵌套仓库、worktree `.git` 文件、当前文档与 cwd 属于不同项目时，目标路径符合第 5 节。
5. 搜索隐藏已选项后生成仍包含它；零结果、零选择、取消、窄窗口和重复开关模板均符合约定。
6. 已有普通文件、空文件、已修改文档、尚未保存的同路径缓冲区、大小写变体和符号链接分支都有集成覆盖；不覆盖、不重复创建。
7. 选择期间目标出现或目标目录消失、取消后后台结果返回，均无错误的文档或磁盘副作用。
8. 固定模板集合生成结果稳定；`!` 顺序完整保留；保留后置重复规则；模板结尾、分段和换行正确。
9. 用真实 Git 的 `check-ignore` 在临时测试仓库验证代表性语义：构建产物被忽略、锁文件保留、dotenv 示例保留、跨模板的否定规则及根锚定路径正确。仅测试使用 Git，产品功能不依赖 Git 可执行文件。
10. 检查所有模板目录 ID、资源、来源与许可；确认没有默认锁文件忽略、源码通配符等违背模板原则的规则。测试应断言可观察的匹配结果，不能只依赖文本快照。
11. 运行相关 Rust 单元 / 集成测试、格式检查与适用的无 Git feature 构建检查；用户文档和默认键位同步更新。

# Helix 中的 .gitignore 编辑补全

设计提案 · 2026-11-19

在插入模式下，用户可以根据眼前的文件、项目类型和正在编辑的规则补完一行。候选同时告诉用户这条规则会匹配哪一层目录。整个过程在本机完成，打开现有文件、编辑新文件和从 `:gitignore` 生成草稿后使用同一套交互。

## 交互

| 用户操作 | 菜单行为 |
| --- | --- |
| 在空行按 `Ctrl-x` | 展示与本项目相关的少量模板规则，以及本目录尚未被忽略的未跟踪项。省略当前已知无效的候选。 |
| 输入 `/tar` | 补为 `/target/`。详情示例为「仅当前目录下的 target 目录 · 本地目录、Rust 模板」。只有模板证据时显示「Rust 模板 · 检测到 Cargo.toml」。 |
| 输入 `tar` | 本地目录候选为 `target/`，详情标「本层及更深层的同名目录」。模板可另列 `/target/` 并解释范围，两者含义不同。 |
| 输入 `/build/` | 展示 build 的直接子项。编辑 frontend/.gitignore 时，从 frontend/build/ 读取。 |
| 输入 `*.` | 从本目录可见的未跟踪普通文件提取扩展名。若有 app.log 和 error.log，显示一条 `*.log`，详情示例为「本层及子目录 · 发现 app.log 等 2 个样本」。这是采样数。 |
| 在 `.env*` 后输入 `!.env` | 优先显示真实存在且被前文排除的 `!.env.example` 等文件。接受后保留行首的一个感叹号。 |
| 在已有规则中间触发 | 例如 `/bu│ild/cache/` 中选 build 时，结果为 `/build/cache/`。`│` 表示光标。仅替换当前路径段，复用已有的分隔符和后缀。 |

遵循现有自动补全开关、输入长度和延时。规则内的目录分隔符、行首的否定符以及扩展名位置的 `*.` 可直接触发。空行只手动触发；首字符为未转义 `#` 的注释行不产生专用候选。菜单沿用现有导航、接受和取消键。接受一次产生一个可撤销的编辑；选中候选查看详情时不会写盘。

首版仅按文档文件名 `.gitignore` 启用，包含子目录文件以及已指定路径、尚未写盘的草稿。共享同一语法的 CODEOWNERS 等文件维持现有补全。在规则行用专用来源接管内置路径与单词候选，避免系统绝对路径或普通单词淹没有效规则。显式配置的 LSP 仍走原管线。关闭自动触发后，手动补全仍可用。

注释行自动触发时同时跳过内置路径与单词来源；手动按 `Ctrl-x` 时可以调用用户已启用的普通补全来源。读取文档最终生效的 `path-completion` 设置（含语言级覆盖）。关闭后，规则行仅提供项目模板，停止为路径和扩展名采样目录，不显示来自目录采样的详情。

## 候选生成与排序

1. 从缓冲区取得当前行及光标两侧文本，识别注释、否定符、起始斜杠、路径段、通配符和转义。对确定的字面目录逐级读取。文件系统候选按字面名称匹配并做 Git 所需的转义，例如 `trace[1].log` 写作 `trace\[1\].log`。规则里的目录分隔符一律写 `/`。保留用户键入的前导空格、作用域和否定符。
2. 复用内置模板条目、标记表和检测证据。模板按单行提取，跳过注释和空行。优先使用当前 .gitignore 所在目录的项目标记；没有本地标记时使用仓库根的检测结果。生成器现有的根目录检测结果可复用，嵌套目录的局部检测单独缓存。路径候选始终相对当前 .gitignore。若路径含无法直接定位的通配目录，如 `**/bin/`，仅给与前缀相容的规则候选。
3. 使用 Git 索引识别已跟踪文件。已跟踪普通文件不进入忽略推荐。目录可能同时含已跟踪和未跟踪内容，详情只承诺对未跟踪项生效。普通规则优先显示能新增忽略效果的候选，例外规则优先显示能重新纳入的候选。目录自身已被排除时，可以沿用户明确输入的目录前缀列出子项，但在子项例外旁标「父目录已被忽略」，并降级。空行手动推荐省略这些子项。
4. 匹配强度按精确、前缀、模糊排列；同等匹配下优先可改变忽略状态的本地路径，其次项目模板，最后是效果未知的候选。相同插入文本和替换范围合并来源。排序平局按名称固定。已知样本在逐条模拟后效果完全相同的候选降级；只有相同规则在当前位置显然重复且中间没有作用相反的匹配时才可省略。没有样本的模板仍可提示。

### 判断规则效果

以文档当前版本为准，比较「移除正在编辑的行」与「在原位置放入候选行」对代表路径的最终效果，两次均保留后续规则。在候选详情中区分「当前规则会改变状态」「后续规则会覆盖」「父目录已被排除」「尚无本地样本」。相同文本在不同位置可能有效，例如 `*.log`、`!keep.log` 之后再追加 `keep.log`。

对真实路径，使用 Git 兼容匹配器，依次考虑全局忽略、仓库 info/exclude、路径祖先到子目录的 .gitignore，并检查被排除的父目录。对当前 .gitignore 注入缓冲区快照，其他路径上的 .gitignore 使用磁盘内容。尊重仓库大小写策略以及 .git 为文件的工作树。不能确定的效果标为未知，保留路径补全；仓库外仍提供本地路径、局部模板和语法说明。无索引数据时，详情也不推断跟踪状态。

## 实现取舍

| 途径 | 能覆盖的交互与代价 |
| --- | --- |
| 扩展通用路径补全 | 复用目录枚举很方便，但通用补全把前导斜杠解释为系统路径。加入模板、例外和行内替换会让其他语言的路径逻辑承担 Git 规则。 |
| 在 Helix 内增加专用补全源（建议） | 可以访问未保存的 Rope 快照、现有模板和补全菜单。新增工作集中在规则上下文、候选计算和异步结果校验。 |
| 独立语言服务器 | 适合以后向多个编辑器分发。需要额外进程、安装配置，以及与现有模板同步的数据接口。 |

接入点是 `helix-term/src/handlers/completion.rs` 的触发判断和 `handlers/completion/request.rs` 的请求分发；模板和项目证据来自 `helix-term/src/gitignore/`。新增来源应沿用补全菜单的过滤、详情、事务和撤销机制。过滤字符串使用当前路径段；插入文本和作用范围由候选单独携带，避免菜单重新过滤掉以斜杠或感叹号开头的结果。多光标仅在各处的解析上下文与可替换段一致时应用同一候选，否则本次不提供专用候选。

后台枚举仅访问一个明确目录，跳过 .git，不跟随目录链接遍历，不解析到当前规则作用域以外。建议起始限额为每次采样最多 4096 项、最多返回 50 条、空行最多 8 条；达到限额时标明结果为部分样本。目录枚举、索引读取及模板检测不在 UI 线程执行。按工作树和目录短时缓存文件系统数据，手动补全刷新缓存；规则结果按文档版本失效。输入变化、切换文档或离开插入模式后，丢弃上下文已过期的结果。目录不可读时保留可用模板；仓库很大时仍可输入、移动和取消补全。

现有内置候选使用显示标签作为过滤文本，菜单还会按模糊匹配分数重新排序。专用候选需携带独立的过滤文本与效果排序信息，在菜单初次展示和继续输入后的两次排序中都使用。其他来源继续使用已有顺序。

## 交付顺序与验收

| 步骤 | 通过条件 |
| --- | --- |
| 1. 路径与菜单接入 | 在根和嵌套 .gitignore 中分别验证 `/tar`、`/build/`、隐藏项、中文名、空格、字面 `#`、`!` 和方括号。Windows 插入正斜杠。注释行安静；关闭自动补全后手动触发有效；编辑其他文件走原路径。 |
| 2. 项目与扩展名候选 | 根有 Cargo.toml，target 尚未创建时仍能选 `/target/`；创建目录后同一插入项合并两种来源。嵌套 Node 项目优先本地标记。用两个未跟踪 .log 文件与一个已跟踪 .log 文件验证扩展名样本数为 2。 |
| 3. 顺序、例外与降级 | 在未保存缓冲区依次验证 `.env*` 后的例外、重复排除、后续覆盖、`build/` 和 `build/*` 后的子项例外。同一组内容另存入临时仓库，用 `git check-ignore` 作为对照。覆盖仓库外、索引不可用及父子 .gitignore 优先级。 |
| 4. 编辑与响应 | 中途补全保留后缀，取消恢复原内容，一次撤销还原整次补全。多光标异构上下文无错位编辑。大目录达到采样上限后仍可继续输入；在后台请求期间切换文档，旧结果不能出现在新文档。 |
| 配置回归 | 无 LSP 时在注释行连续输入不弹菜单，手动可获取已启用的普通候选。使用语言级配置关闭路径补全后，在带 Cargo.toml 的目录仍可手动取得 Rust 模板，真实路径及扩展名采样候选消失。 |

后续扩展为**当前规则的效果预览**。用户主动查看时列出若干受影响的未跟踪路径，显示最后起作用的规则及其文件和行号。首版菜单只解释所选候选及其有限样本，仓库级预览另行按需计算。

Git 匹配语义参照 [gitignore 官方文档](https://git-scm.com/docs/gitignore)。

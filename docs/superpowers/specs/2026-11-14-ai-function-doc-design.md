# Helix AI 函数文档注释设计

日期：2026-11-14

状态：用户已确认并要求实现；实现与验收记录另见验证文档。

## 1. 已确认的需求与设计目标

用户希望为 Helix 的 vibe coding 增加第一个主动代码操作：给光标所在函数添加函数注释。

用户已确认：

- 第一版支持 C、C++、Python。
- 注释默认使用中文。
- 采用 Helix 原生命令，复用当前模型服务。
- 注释使用“restructure”格式。本设计将其理解为 reStructuredText（reST）；这是术语解释，交付时明确告知用户。

目标：光标停在函数中，执行命令，看到正确函数的中文 reST 注释，确认后一次插入并可一次撤销。

本文其余默认值和范围限制最初由实现方建议，用户已随整份方案确认并要求实现。

## 2. 方案选择

| 方案 | 优点 | 代价与限制 | 结论 |
| --- | --- | --- | --- |
| Helix 原生命令 + 现有模型服务 | 可使用内存中文档、语法树、事务和版本校验；自然支持预览与撤销 | 需要增加命令、操作状态和预览组件 | 用户已选择 |
| 外部脚本生成并写回 | 原型实现快 | 难以可靠处理未保存内容、异步版本变化和撤销 | 不采用 |
| 通用聊天面板执行指令 | 可覆盖更多自由操作 | 首个功能需要更多界面与编辑代理设施 | 暂不建设 |

本次增加一个有明确输入输出的 AI 操作，并提取必要的共用模型通信能力；不预先搭建插件系统、通用代理或工具调用框架。

## 3. 现有代码与复用边界

- `helix-term/src/handlers/ai_completion/client.rs`：OpenAI 兼容聊天调用、鉴权、响应读取；目前混合了补全提示词、输出裁剪和补全专用限制，不能直接拿 `complete()` 生成注释。
- `helix-term/src/handlers/ai_completion/server.rs`：llama.cpp 子进程生命周期和就绪等待；目前受 `AiCompletionConfig.enabled` 控制。
- `helix-term/src/handlers/ai_completion.rs`：异步取消、事件订阅、通过 job 回到编辑器线程提交结果，可借鉴流程；文档操作不沿用“任何光标移动都取消”的补全策略。
- `helix-term/src/handlers/ai_completion/context.rs`：已有围绕语法树提取签名和上下文的代码，可提取小型通用辅助函数。
- `runtime/queries/{c,cpp,python}/textobjects.scm`：已有函数文本对象；C++ 也包含 lambda，不能将所有 `function.around` 捕获直接视为可添加文档的具名函数。
- `helix-term/src/commands/typed.rs`：注册冒号命令。
- `helix-term/src/ui/popup.rs`：可承载滚动预览；需要专用内容组件处理确认、取消、重新生成与完整消费按键，不能直接使用会把未知按键传给编辑器的默认行为。
- `helix-view/src/ai_completion.rs` 与 `helix-view/src/editor.rs`：现有模型设置及编辑器配置入口。

## 4. 命令和用户行为

新增拟定命令 `:ai-doc`，只在命令被正式提交时启动请求，不在命令输入过程中请求。配置快捷键时使用现有 typable command 绑定方式，例如：

```toml
[keys.normal.space]
D = ":ai-doc"
```

第一版不增加默认快捷键，避免占用用户键位。命令名与示例均为拟新增能力。

行为：

1. 检查只读状态、语言、单光标、无活动 snippet、模型设置，并定位函数和插入点。
2. 发现已有文档或不能可靠定位时，立即解释原因，不调用模型。
3. 显示简短生成状态；请求在后台执行，编辑器保持响应。提供 `:ai-doc-cancel` 取消在途请求。
4. 结果校验通过后打开预览，显示函数名、位置及最终将插入的源码文本，可滚动查看。如果另一 prompt/picker 正在交互，先暂存结果并提示生成完成，待返回原编辑视图且其他模态交互结束后再打开；等待期间仍执行全部失效校验，不能抢占用户当前输入。
5. 预览中 `Enter` 接受、`Esc` 或 `Ctrl-c` 取消、`r` 重新生成；其他编辑按键不穿透到底层。第一版不在预览里直接编辑文字。
6. 接受时再次验证目标，使用一个独立编辑事务插入；不自动保存，不触发文件级格式化。
7. 保留原代码位置上的逻辑光标，通过事务映射位移，不把光标强行跳到注释末尾；新注释在当前视图中可见。

预览前不改变正文、dirty 状态、撤销历史或 LSP 文档版本。Python 接受后会新增 `__doc__` 元数据；原有语句和表达式保持原样，不承诺运行时对象完全不变。

只有一个活动的手动 AI 文档操作。再次执行 `:ai-doc` 取消旧操作，以新目标为准。重新生成复用仍然有效的原始快照，不积累多个候选。

## 5. 目标函数和插入位置

语法树确定编辑范围，模型不能返回范围、文件路径、源码补丁或编辑命令。选择包围光标的最内层具名函数；如果最内层可调用结构是匿名 lambda/闭包，提示不支持，避免意外给外层函数写注释。

单个普通选区允许存在，但只使用主光标所在位置，不使用选区推断目标；多光标拒绝。不寻找“最近的下一个函数”。无语法树、目标结构包含无法可靠解析的错误或不支持的包装结构时提示失败。

定位沿当前文件宿主语言的根树（现有 `syntax.tree()`），不能直接沿用按光标选取注入层的上下文遍历，避免 Python 字符串中的注入语言遮蔽所属函数。字节与字符位置必须显式转换；函数结束边界等于文档长度是合法情况。光标位于 EOF 时，仅在最后一个字符确属候选函数范围时允许向前定位一个字符，不跨末尾空白行寻找上一个函数。

### Python

- 支持 `def`、`async def`、方法、嵌套具名函数和装饰器包装的定义。
- 光标在装饰器上时关联该装饰器包裹的函数。
- 将三双引号 docstring 插入函数体的第一个语句位置之前，使用函数体缩进和原文档换行符。原有首部注释可以保留在前面，docstring 仍须成为第一个语句。
- 识别已有首语句字符串文档，包括单/双引号、三引号、合法 raw/unicode 前缀及隐式连接的字符串；不把 bytes 或 f-string 当成 docstring。
- `self`/`cls` 仅在语法上确认为隐式实例/类接收者时省略，不能简单按变量名过滤；静态方法、普通函数同名参数仍保留。装饰器无法确认时保守保留。
- 处理位置参数、仅关键字参数、`*args`、`**kwargs`，不为 `/`、`*` 分隔符创建参数说明。
- 第一版拒绝单行函数体（例如 `def f(): return 1`），因为插入多行 docstring 需要重排原有代码；给出改成多行函数的提示。
- 生成器在摘要/详情说明逐项产生的值，返回字段描述生成的迭代器；异步函数描述 await 后的结果，不虚构额外协程行为。

### C / C++

- 支持具有函数体的具名函数和方法，包括能够可靠解析的构造/析构、运算符重载、模板及属性包装。
- 插入 `/* ... */` 块注释，放在该函数关联的模板头、属性等声明前缀之前，保持原有缩进；不能插到模板头与函数之间或属性内部。
- 通过完整声明包装节点确定插入位置。若函数与其他代码共享同一行，或无法可靠找到独立声明边界，则提示暂不支持，避免把注释附到其他实体上。
- `extern "C"`、namespace、类和预处理分支整体不移动；仅在所处边界内插入。
- 第一版不处理只有声明的头文件原型、纯虚函数声明、`= default` / `= delete`、宏展开函数或 C++ lambda。头文件里有函数体且满足上述条件的函数仍可支持。
- C++ 构造/析构和 `void` 函数省略返回字段。模板参数使用 `:tparam T:`。C++ 异常用 `:throws Exception:`，C 错误码写入返回说明。
- 未命名参数无法得到准确参数字段名时提示暂不支持，不发明参数名。

## 6. reST 格式规范

统一结构：中文一句话摘要；确有必要时追加详情；空行；参数字段；返回字段；有直接证据的异常字段。按签名顺序描述参数，代码标识符保持原样。

Python 字段为 `:param name:`、`:type name:`、`:returns:`、`:rtype:`、`:raises Error:`。默认只为源码中明确给出的类型注解生成类型字段，未知类型省略，不猜测。无有意义返回值时省略返回说明；已有明确 `None` 注解可保留 `:rtype: None`。

C/C++ 使用 `:param name:` 和 `:returns:`；类型已在签名中体现，第一版不重复输出类型字段。C++ 增加 `:tparam name:` 与 `:throws Error:`。不使用 Doxygen 的 `@param` 标签，不生成完整 `.. cpp:function::` 指令。

示例输出与源代码一同展示：

```python
def divide(a: float, b: float) -> float:
    """计算两个数的商。

    :param a: 被除数。
    :type a: float
    :param b: 除数。
    :type b: float
    :returns: 两数相除的结果。
    :rtype: float
    :raises ValueError: 当除数为零时抛出。
    """
    if b == 0:
        raise ValueError("b must not be zero")
    return a / b
```

```cpp
/*
 * 计算两个整数中的较大值。
 *
 * :param a: 第一个整数。
 * :param b: 第二个整数。
 * :returns: 两个整数中的较大值；相等时返回该值。
 */
int larger(int a, int b) {
    return a > b ? a : b;
}
```

这里保证生成 reST 内容的源码注释。Python 可由配置好的 Sphinx autodoc 获取 docstring；C/C++ 块注释不会因为使用 reST 字段就自动被 Sphinx 提取。项目所用源码提取器与发布文档构建不属于第一版集成范围。

格式依据：

- [Sphinx Python info field lists](https://www.sphinx-doc.org/en/master/usage/domains/python.html#info-field-lists)
- [Sphinx C function fields](https://www.sphinx-doc.org/en/master/usage/domains/c.html)
- [Sphinx C++ info field lists](https://www.sphinx-doc.org/en/master/usage/domains/cpp.html#info-field-lists)
- [Sphinx autodoc](https://www.sphinx-doc.org/en/master/usage/extensions/autodoc.html)

## 7. 已有注释策略

第一版只添加缺失的文档，不提供强制覆盖参数或自动合并。

- Python：已有 docstring 时提示“当前函数已有文档注释，未修改”；普通 `#` 实现注释可以保留。
- C/C++：函数声明包装之前紧邻的 `/* */` 或 `//` 注释组均保守视为可能已有说明，跳过并提示。判断相邻时将模板/属性作为函数包装的一部分。
- “紧邻”指注释尾部与声明起点之间只有空白且没有空白行。注释包含 `:param`、`@param` 等内容也不改变这个邻接规则。
- C/C++ 前面存在空白行分隔的文件/章节注释不阻止生成；无法确定归属时保守跳过，并说明原因。
- C/C++ 函数体内的实现注释不等同于函数前文档，不阻止生成。

## 8. 上下文与模型输出

必须来自当前内存文档，包括未保存的编辑。发送函数完整签名与完整函数体，加上有界的所属类/namespace、相关类型及 imports/includes；优先当前文件，不搜索其他项目文件，不启动 LSP 请求作为前置依赖。

保留函数完整性，不能为了凑预算只发送开头再宣称理解全函数。上下文不足时先去掉辅助声明，再检查完整目标；仍放不下则在请求前提示函数超出预算。嵌套定义属于函数原文，但提示模型只为目标函数生成文档。

复用模型连接、鉴权和服务就绪机制，独立使用文档提示词和生成参数，不能套用补全的 64/128 token 上限。建议非流式、低温度、关闭 thinking，默认输出预算 768 tokens、请求超时 30 秒；本地模型加载沿用独立启动超时。

建议模型返回受约束的语义 JSON：摘要、可选详情、按名称索引的参数描述、可选返回说明、可选异常说明、可选模板参数描述。由编辑器构造固定 reST 字段、注释定界符、缩进和换行。

- 参数名和模板参数名必须来自语法树；拒绝重复、缺失必需参数或额外名称。`self`/`cls` 是否省略由定位层决定。
- 类型字段由源码提取，模型不负责改写类型。
- 每个说明字段是纯文本，可使用安全的内联代码标识。首版不接受任意 reST 指令或由模型返回的字段行，避免字段注入及不受控结构。
- 仅记录在函数中明确出现或可由当前上下文直接确认的错误、资源释放、参数变更、前置条件；不假定被调用函数的异常、线程安全或外部契约。
- JSON 无效、字段为空、超过长度、输出被 token 限制截断、代码围栏/解释/工具调用等不符合协议的结果，均显示失败并允许重试，不将半成品插入。
- Python 文本需正确转义反斜杠和三引号，使解析后的 docstring 与预期内容一致；C/C++ 不允许生成内容中的 `*/` 提前结束注释，可以拒绝该结果并提示重试。
- 客户端将源码视为数据，不遵从其中的模型指令；不执行模型提供的命令。

结构校验可防止错误名称和越界编辑，不能证明自然语言描述在语义上一定正确；用户仍通过预览审阅内容。

上下文预算必须同时覆盖系统指令、结构化输出要求、聊天模板、函数正文、辅助声明和输出预留，并与运行模型的窗口核对。现有默认 `context_size = 4096` 不能被当作可无限添加函数文本。优先使用可用的模型分词计数；无计数能力时使用针对当前模型验证过的保守估算，不通过扩容或截断悄悄改变用户模型设置。外部服务拒绝上下文过长时给出明确错误。

## 9. 状态、取消与自动补全共存

操作状态：Idle → Generating → Ready（有其他模态交互时暂存）→ Preview → Applied / Canceled / Failed；无需等待时可直接进入 Preview。

请求快照至少包含 operation id、DocumentId、ViewId、文档版本、函数范围及签名、插入锚点、模型/配置代次。预览和最终应用都必须检查仍为当前操作、文档仍可编辑、版本和目标有效、视图仍存在。

- 生成过程中仅在原视图内移动光标或滚动不取消；结果仍指向触发时的函数，预览显示其名称和行号。
- 任意正文编辑（包括其他视图的编辑、LSP 编辑、撤销和重做）立即使该文档操作失效；不尝试将旧结果重定位到新版本。
- 切换文档/视图、关闭目标或修改有关配置时取消；即使切回也不能恢复旧操作。
- 异步任务取消之外仍做响应和应用校验，避免取消后已排队的 job 写回。
- 用户显式取消、结果应用或失败后，均释放手动操作所占状态，不遗留补全暂停标志。
- 手动请求和预览期间清除现有 AI 灰字、取消自动补全请求，暂停新自动请求；结束后由下一次正常输入恢复补全。
- 不改变普通 LSP/路径/单词补全的配置；预览打开前需妥善结束已有补全临时预览，不能把临时文本当成真实上下文。
- 单模型资源串行协调，手动操作优先。取消 HTTP 请求不能保证远端立即停止推理；仍保持 UI 可响应并防止过期结果提交。
- 宏录制/重放期间首版拒绝发起 `ai-doc`，防止重放时生成不确定注释。

## 10. 配置与服务生命周期

新增独立操作配置，建议：

```toml
[editor.ai-doc]
enabled = true
language = "zh-CN"
style = "rest"
timeout-ms = 30000
max-tokens = 768
```

这些是拟新增配置。`AiDocConfig.enabled` 默认关闭，示例显式开启；默认描述语言为 `zh-CN`。该功能仅手动执行，`enabled = true` 不代表自动发生成请求。`style` 首版只接受 `rest`；`language` 首版支持 `zh-CN`，可同时实现简单的 `en` 选项，具体由实现者决定并写明。

为保持已有用户配置，第一版模型 endpoint/model/api-key-env/model-path/server-path/context-size/gpu-layers/startup-timeout-ms 继续读取现有 `[editor.ai-completion]` 中的设置，不复制凭据，也不强制迁移到新 `[editor.ai]`。说明文档必须解释这个暂时的共用关系。

从现有配置构造内部共用的模型设置，模型服务是否需要运行取决于 `ai-completion.enabled || ai-doc.enabled`。`ai-completion.enabled = false` 只禁用自动补全，不能使手动文档命令失效。服务就绪检查也必须使用共用模型状态，不能继续检查补全专用 enabled 值。

保持原有服务启动策略，不因 `ai-doc` 创建第二个本地模型进程。只有配置了模型路径并且至少一个功能启用时才管理现有本地服务；外部 endpoint 仍沿用当前连接方式。模型配置变化使所有在途 AI 操作失效，操作独有的超时或 token 修改无需重启模型。

不在本次设计中修改用户本机配置、启动模型或承诺现有端点可连接；真实服务验证安排在后续实现验收。

## 11. 建议模块边界

文件名为实现方建议，可以在不改变行为的前提下调整：

| 位置 | 职责 |

| `helix-term/src/handlers/ai_doc/target.rs` | C/C++/Python 目标和注释锚点、已有文档判断 |
| `helix-term/src/handlers/ai_doc/context.rs` | 完整函数和辅助声明的预算收集 |
| `helix-term/src/handlers/ai_doc/format.rs` | JSON 校验、reST 和语言注释渲染 |

| 共用 AI 模块 | 从现有补全提取最小模型配置、HTTP 传输和服务管理；保持补全行为 |
| `helix-term/src/commands/typed.rs` | `ai-doc` / `ai-doc-cancel` 注册 |

网络响应只产生文档内容。仅在编辑器线程对通过校验的插入计划创建 Transaction；提交独立撤销边界，不能与之前输入或后续编辑合并。

## 12. 验收与验证

目标定位与格式验证：

1. C、C++、Python 的函数签名与函数体各处触发均定位正确；嵌套具名函数取最内层，匿名函数不误选外层。
2. Python 装饰器、多行签名、async、方法、参数分隔符、`*args`/`**kwargs`、缩进和 CRLF 均正确；单行函数按约定拒绝。
3. C/C++ 模板、属性、重载、构造/析构、同一行多个实体、头文件定义与纯声明的支持边界符合设计；原声明顺序不改变。
4. 已有文档按策略跳过；重复执行不会堆叠注释。C/C++ 与章节注释间的空白行判定有固定样例。
5. reST 参数顺序、语言专属异常字段、类型来源、void/None、生成器和模板字段正确；不混入 Doxygen/Google/NumPy 格式。
6. JSON 错误、未知/重复/缺失参数、超长/截断响应、定界符和转义不会生成破损源码。

编辑器及异步验证：

7. 预览前文档文本、dirty、撤销历史和 LSP 版本不变；取消不留下任何编辑。
8. 接受仅插入注释，保留原语句；一次 undo 恢复原文，一次 redo 重放已接受文本，不重发模型请求。
9. Python 插入后重新解析，只允许新增首个 docstring 的结构变化；C/C++ 插入后语法有效，源码既有 token 不改变。Unicode、反斜杠、三引号、CRLF 均有样例。
10. 文档编辑、撤销、视图切换、配置变更、重复请求、延迟/乱序响应、预览中失效、只读切换等均不能应用旧结果。
11. 预览滚动、取消、重新生成和键盘输入隔离正确，不会接受普通补全菜单中的候选。
12. 自动补全关闭而 ai-doc 开启时能使用现有模型；共享服务只启动一个进程，文档操作结束或失败后自动补全可恢复。

模型请求使用可控 HTTP 假服务验证协议、错误、超时和乱序；这不替代真实质量验证。实现完成后，在用户当前模型可用的前提下，至少用 C、C++、Python 各两个真实函数检查上下文、中文语义、reST 输出、延迟及超预算提示，明确报告人工评估结果和局限，不虚报准确率。

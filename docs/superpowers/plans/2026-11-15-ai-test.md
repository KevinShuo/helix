# AI Test Generation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Generate, preview, integrate and optionally run C/C++ GoogleTest and Python pytest tests from Helix.

**Architecture:** Reuse the shared AI provider and model lease infrastructure.
Deterministic project adapters own paths and CMake changes; models produce only
test code and assumptions. Editor buffers own accepted changes, and saved snapshots
gate execution and one diagnostic-driven repair.

**Tech Stack:** Rust, Tokio, tree-house, reqwest/serde, CMake/CTest/GTest, pytest.

**Spec:** docs/superpowers/specs/2026-11-15-ai-test-design.md

## Global Constraints

- Preserve all pre-existing uncommitted work; work in current checkout on a codex branch.
- Prefer existing/local/vcpkg GTest, then permit pinned FetchContent.
- No automatic business-code edits, dependency installation, cloud fallback or shell commands from models.
- Defaults: disabled, 4096 final tokens, 120s generation, 180s runner stage timeout, one repair.
- Accepted modifications remain undoable editable buffers; save before execution.

## Review Focus

- Previously documented functions must still generate tests.
- CMake comments/strings/nested scopes and ambiguous target mappings must not cause guessed edits.
- Dirty buffers, changed dependencies and deleted paths must invalidate application/execution.
- Multi-config/vcpkg projects and missing dependencies need actionable errors.
- Failed assertions and zero collected tests cannot be reported as successful or silently repaired.

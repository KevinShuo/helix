# New File Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan in the current session. Track steps below.

**Goal:** Add `Space n` and `:new-file <path>` to open a new named buffer beside the current file, writing only on save.

**Architecture:** Reuse `Prompt` and `Editor::open`; share path resolution and collision validation between the prompt and typed command. Preserve the existing `:new` command and save behavior.

**Tech Stack:** Rust, existing Helix terminal UI and Tokio integration tests; no new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-14-new-file-design.md`

## Global Constraints

- Relative paths use the current buffer's parent, falling back to editor cwd.
- No disk writes until save, including nested directories.
- Reject existing disk entries and named buffers; cancellation is inert.
- New buffers enter insert mode; `:new` stays unchanged.

## Review Focus

- Cwd differs from the current buffer's directory.
- Scratch-buffer fallback and paths containing spaces or Unicode.
- Disk collisions and unsaved-buffer collisions preserve existing contents.
- Empty input, directory targets, and Escape leave the original buffer active.
- Nested paths stay absent until explicit save, using existing `:w!` rules.

# DeepSeek 开启思考、16K 预算：6 个样例完整复测

日期：2026-11-15。**本轮 6/6 通过生产格式校验、真实编译和原实现测试，18/18
个固定缺陷全部检出，无截断；生成中位耗时 23.2 秒。** 没有重试、自动修复或
人工修改生成代码。结果来自固定小样本，不代表一般准确率或测试安全性保证。

总生成时间 **130.4 秒**，总 completion tokens **29316**。所有回复均以 `stop`
结束，思考元数据非空。每个目标完成缺陷实验后恢复原源码，6/6 再次通过。
缺陷实验的重复构建时间不计入上表生成时间或普通使用延迟。

相比上轮 4096-token 思考补测的三次截断，本轮每份用量为 2382～6265，16K
有充分余量。但没有在 8192 预算下另跑一轮，不能把观测用量直接当作较小预算
下同等稳定性的证明。例如本轮 C++ 合并区间只用了 2382，上轮相同提示词在
4096 上限却截断；生成路径会随条件或采样变化。

## 生成质量观察

- **C linkage 已正确处理。** 两个 C 测试均在 `extern "C"` 中包含 `subject.h`，
  没有再出现遗漏 C linkage 或 C/C++ 重复声明冲突。
- **gtest 宏语法已正确处理。** 区间合并的带逗号初始化列表用括号保护，原始
  输出直接编译通过。覆盖共享端点、相邻不合并、倒序/嵌套/重复区间和输入不变。
- **额度状态断言正确。** 包含精确耗尽、耗尽后消费 0 成功、拒绝后状态不变、
  负额度及连续消费，未出现本地旧样例的零消费预期错误。
- **Python 结构和契约检查完整。** 两份响应都包含必需的 `assumptions`。端口
  测试使用参数化覆盖非法字符、Unicode 数字、符号和范围；去重测试检查首项
  保留、顺序、输入不变、回调调用次数、异常传播及非 list 输入。
- **仍有测试自身的安全问题。** `copy_prefix` 部分测试把目标数组全填成非零
  字节后使用 `EXPECT_STREQ`。在遗漏 NUL 的缺陷下，失败诊断可能越界读取。
  截断/容量 1 等其他有界字节断言也独立发现该缺陷，所以本轮 3/3 检出不需要
  依赖不安全诊断；代码保留原样，没有为评分修复。生产使用应先用有界断言验证
  终止符或直接比较有界内容。

独立只读审查核对了所有计数、输入哈希和六份代码，没有发现其他实质性语义错误。
通过这 18 个缺陷仍不等于覆盖充分，以上字符串安全问题尤其说明需要保留审查。

## 参数、控制和配置范围

- 请求模型 `deepseek-flash`，开启思考，沿用接口默认 high 强度；总输出预算
  `max_tokens=16384`，含思考和最终代码。参数含义见
  [官方 API 文档](https://api-docs.deepseek.com/api/create-chat-completion/) 和
  [思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)。思考模式
  不使用 temperature 控制采样，虽然请求仍保留原来的 0.0 值。
- 上下文预留为 32768，请求超时仍 120 秒。与上轮所有六份 messages 在发送前
  逐项相等，完成后再次核对；更大上下文没有带入额外源码。
- 完整沿用原 6 个合成目标、公开契约和 18 个缺陷；未发送真实项目业务代码。
- 使用生产提示词、共享 HTTP transport、输出校验、CMake/vcpkg gtest、pytest。
  不手改生成的测试，不忽略失败，不用补测覆盖本轮首发结果。
- **这是评测参数。** 当前产品 `ai-test.max-tokens` 配置上限为 8192，本轮只在
  `cfg(test)` 的评测请求中覆盖总预算到 16384。日常 provider/思考开关及配置文件
  没有修改。若要让编辑器日常按 16K 总预算运行，还需调整产品配置约束和预算策略。

这组结果支持继续试用“DeepSeek 思考＋较大输出预算”作为质量优先的测试生成
选项；速度优先可保留非思考，离线需求可保留本地 27B。当前证据仍来自单轮小样本。

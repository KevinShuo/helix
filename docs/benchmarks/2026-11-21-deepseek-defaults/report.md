# Helix 的 DeepSeek 默认设置实测

2026-11-21 在 Windows 笔记本上调用 DeepSeek 官方 API，比较 `deepseek-flash` 和 `deepseek-v4-pro`。按每项功能先选通过样例最多的设置，再选中位耗时最短的设置。行内补全按用户偏好使用本地模型，云端只作对照。

## 结果

每格依次给出质量和中位耗时。测试生成一行的分子是成功检出的缺陷数，其他行的分子是通过的样例数。

| 功能 | Flash 直答 | Flash 低强度 | Pro 直答 | Pro 低强度 |
|---|---:|---:|---:|---:|
| 行内补全 | 25/30 · 0.53 秒 | — | 27/30 · 1.05 秒 | — |
| 函数文档 | **6/6 · 1.33 秒** | 6/6 · 9.17 秒 | 5/6 · 2.63 秒 | 6/6 · 37.40 秒 |
| Git 提交 | 4/6 · 1.48 秒 | **6/6 · 2.65 秒** | 5/6 · 3.37 秒 | 5/6 · 12.50 秒 |
| 冲突合并 | 7/8 · 0.98 秒 | **8/8 · 1.14 秒** | 8/8 · 1.66 秒 | 8/8 · 3.83 秒 |
| 测试生成 | 9/12 · 4.25 秒 | **12/12 · 9.04 秒** | 8/12 · 8.20 秒 | 12/12 · 34.42 秒 |

- **行内补全**。将输出插入 30 个 Python、C++ 代码缺口，执行语义检查。Flash 给了 5 条错误建议。Pro 给了 2 条错误建议，另有 1 次未给建议。这台机器前次用同组样例测试本地 Qwen2.5-Coder-3B，结果为 16/30，请求中位耗时 0.95 秒。两次测试使用同一题集，时间段不同。
- **函数文档**。检查 Helix 能否解析并渲染文档，再按样例核对正常行为与边界，包括空输入、端口范围、引用参数修改、异步迭代和异常。Pro 直答在异常样例中泛称转换失败会返回 `None`，没有说明函数只捕获 `ValueError`。
- **Git 提交**。检查文件选择、部分暂存的保留、逐文件说明、提交类型和消息。Flash 直答有两次返回的文件摘要字段无法解析。第二轮通过 Helix 原生 DeepSeek 线路与自动预算独立复测同六题，直答 4/6、1.46 秒，低强度 6/6、3.17 秒。
- **冲突合并**。八题覆盖 JSON 和 Python。检查块 ID、解释、合并状态、生成内容及边界行为。需人工处理的冲突以正确请求人工介入为通过。Flash 直答在一题已有明确草稿选择时仍要求人工介入，低强度按要求保留了草稿。
- **测试生成**。用两个 Python 函数、一个 C 函数和一个 C++ 函数，在原始实现与每题三个各自独立的缺陷实现上运行生成的测试。Flash 直答生成的一组 C++ 测试编译失败。Pro 直答生成的一组 C 测试未通过 Helix 套件名校验，C++ 测试漏检一个缺陷。Flash 低强度、Flash 高强度和 Pro 低强度均在四个正确实现上通过、检出全部 12 个缺陷，耗时依次为 9.04、26.84 和 34.42 秒。

## 测量范围

主对照共 156 次功能操作，另有 4 次 Flash 高强度测试生成和 12 次原生 Git 复测。使用合成样例并混排请求，每批最多并发 5 次。主对照以非流式完整结果计时，包含失败样例，行内输出上限为 48 tokens，其余功能为 8192 tokens。Git 操作可包含多个请求。测试生成时间截至收到模型结果，随后单独编译、执行测试和验证缺陷。云端行内耗时从发起请求起算，未计入键入防抖或屏幕绘制。每个配置每题一次，Git 单独复测了一轮。网络状况、项目规模和生成的具体内容都会影响实际体验。

Windows 验证还发现 CTest 向 GoogleTest 传递部分中文用例名时，可显示通过却运行零条用例。修复后，Helix 通过 ASCII 套件名运行生成的测试。详细日志确认执行了 Flash 低强度生成的全部 11 条 C++ 用例，三个独立缺陷均使测试失败，恢复正确实现后再次通过。

共享配置通过 `[editor.ai.deepseek-thinking]` 给 `commit`、`merge`、`test` 设为 `"low"`，文档继承 Flash 的直答设置。路由选定 DeepSeek 后才应用这些值，面板中的显式选择优先。各轮结果、毫秒耗时和主对照 token 用量见[逐项记录](cases.csv)。思考参数的含义见 [DeepSeek 官方说明](https://api-docs.deepseek.com/guides/thinking_mode/)。
